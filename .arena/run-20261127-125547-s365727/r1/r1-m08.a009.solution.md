# Build plan: 2D floor plan to 3D model

## Recommendation
Split the job in two halves joined by one editable JSON file (the "plan spec"). Half 1 turns the image into the spec (walls, openings, rooms, scale). Half 2 turns the spec into geometry, a GLB and renders. Accuracy problems then live in one visible text file. Build half 2 first with a hand-made spec (deterministic, quick), then automate half 1.

## Assumptions
- Input: a clean architectural plan (image, scan or PDF page) with at least one printed dimension. Hand sketches and photos are out of scope for v0.
- One storey, straight walls, 2.4 to 2.7 m ceilings. Curves, stairs, roofs and multi-storey come later.
- Cloud container with Python 3, Node, Chromium and Playwright (given). I assume `pip install` works through the proxy. Blender is not stated as installed, so it is optional; check with `python -c "import bpy"`.
- "Accurate" means every wall face within 2 percent of the printed dimension, not survey grade.
- Headless Chromium uses software GL: works but slow. Test on the first render.

## Three approaches, one chosen
1. AI image generator straight from the plan: fast and pretty, but invents or drops walls, gives no measurable or exportable geometry. Optional polish step only, checked against the plan.
2. Pure three.js tracing polylines in the browser: good viewer, awkward for tracing, opening cuts and print renders.
3. **Python spec-driven pipeline with a swappable builder (chosen).** Image to JSON, then JSON to mesh (shapely/trimesh to GLB, viewed in three.js), later Blender `bpy` for polish.

## Architecture
```
plan.png/pdf
 [1 Prepare]  PDF->PNG (pymupdf), deskew, binarise            (OpenCV)
 [2 Scale]    px_per_m from known dimensions, cross-checked
 [3 Extract]  walls, openings, rooms in PIXELS -> plan.json
 [4 Verify]   overlay on original, human OKs (loop, see below)
 [5 Build]    plan.json -> 3D (builder A, later B)
 [6 Export]   plan.glb, plan.blend (B), renders, plan.json
```

### The plan spec (contract between halves)
Stored in pixels, so the overlay is exact and metres are derived:
```json
{
 "image": "plan.png",
 "scale": {"px_per_m": 118.4, "origin_px": [212, 96], "refs": [{"a":[212,96],"b":[804,96],"printed_m":5.00,"kind":"outer_face"}]},
 "wall_height": 2.6, "default_thickness_m": 0.2,
 "walls":   [ {"id":"w1","a_px":[212,96],"b_px":[804,96],"t_m":0.20,"ref":"centre"} ],
 "doors":   [ {"wall":"w1","at_m":1.2,"width_m":0.9,"height_m":2.05,"swing":"in","hinge":"left"} ],
 "windows": [ {"wall":"w1","at_m":3.0,"width_m":1.2,"height_m":1.2,"sill_m":0.9} ],
 "rooms":   [ {"name":"Kitchen","type":"kitchen"} ]
}
```
- Wall endpoints are image pixels (centreline). Metres are computed as `(px - origin_px) / px_per_m`, y flipped at build. Origin is the pixel of the building's outer corner, named explicitly.
- Openings are offsets in metres along their host wall (measured from its `a` end), so they cannot drift off the wall.
- Room polygons are not typed in; they are derived by polygonize (see accuracy) and labelled by the room `name` whose label point falls inside.

## Pipeline

### Steps 1 and 2: prepare and scale
- PDF to PNG at 200 to 300 dpi with `pymupdf`. A vector PDF is the best case: read line segments from the page's drawing commands (`page.get_drawings()`) and skip image processing.
- Scale sources, in order: (1) user gives one length and two pixel points; (2) OCR of a dimension string (`pytesseract`, or Claude reading the image) paired with its dimension line; (3) scale bar or a standard 0.9 m door as a sanity check only.
- Gate (consistent with the 2 percent goal): compute px_per_m from the longest reference, then check every other reference.
  - All residuals under 1 percent: proceed.
  - 1 to 3 percent: build, but print per-dimension residuals and flag the model "approximate".
  - Over 3 percent: the plan is likely not drawn to scale. Do not silently build. Offer two defined routes: anchor on the one dimension the user trusts (usually overall width) and report where the others then disagree, or build in "relative" mode with unitless proportions and a visible banner.

### Step 3: extract
| Option | How | Speed | Accuracy |
|---|---|---|---|
| A. Vision-assisted | Claude reads the image and proposes pixel coordinates; a snapping script refines them | Fastest, today | OK on simple plans only after step 4 loops |
| B. Classical CV | threshold, morphological open with long kernels to keep thick lines, `HoughLinesP` or contours, snap to H/V, merge collinear, thickness from line width | Hours | Good on clean CAD plans, poor with hatching and text |
| C. Trained model | public floor-plan segmentation work exists (for example CubiCasa5k-derived); licences and quality unchecked, a lead only | Days | Best in-distribution |

Vision output is not pixel-accurate, so option A is made accurate by a **snap-to-ink pass**: for each proposed wall, search a few pixels either side in the binarised image and move the endpoints and offset to the nearest ink centre (and take thickness from the ink width). Then step 4. Use A for v0, add B for volume, skip C until both fail.

Openings: doors are gaps in a wall line, usually with an arc; windows are thin double lines inside a wall. Detect as gaps or breaks, record offset and width on the host wall. Paint OCR text boxes white first so letters are not read as walls.

### Step 4: verify (budgeted loop)
`overlay.py` draws the spec over the original from pixel coordinates (walls red, doors green, windows blue, wall ids as labels) into `overlay.png`. Expect 2 to 4 edit rounds for a typical one-storey plan: look, edit the JSON, rerun (seconds each). Stop when no wall is visibly off the ink by more than its thickness.

### Step 5: build
**Builder A (v0, no Blender, no 3D booleans)**
- Convert pixels to metres. Buffer each centreline by t/2 with `shapely`, `unary_union` into one wall footprint.
- Openings: subtract a rectangle per opening from the footprint to get wall bands; extrude them to full height. Add header bands above doors (door height to wall height) and sill and lintel bands for windows by extruding the same cut rectangles over the vertical ranges only.
- Fill the openings: door leaf (thin box, 0.04 m, rotated by the swing angle, about 70 degrees open for a visible swing, hinge side from the spec) and frame; window frame (four thin boxes) plus a glass pane (thin box, transparent material). Name every mesh (`wall_w1`, `door_d1`, `glass_win1`).
- Floors: for each derived room polygon, `trimesh.creation.extrude_polygon` 0.1 m down (needs `mapbox-earcut` or `triangle`). Material table maps room `type` to a PBR colour: kitchen and bath to tile grey, bedroom and living to wood, default to light grey. Walls off-white, ceilings omitted for the top view.
- Export `plan.glb` via `trimesh.Scene.export`.

**Builder B (v1, optional)**: Blender background (`blender --background --python build.py -- plan.json`) or pip `bpy`. Real boolean modifiers, image textures, area lights, Cycles CPU render (do not assume EEVEE without a GPU). With a Blender MCP add-on on the user's own machine, the same script can run live; a convenience only.

### Step 6: outputs
| File | From | Use |
|---|---|---|
| `plan.json` | step 3 | source of truth; edit and rebuild |
| `overlay.png` | step 4 | proof extraction matched |
| `plan.glb` | A or B | web, AR, any viewer |
| `plan.blend` | B | editing in Blender |
| `top.png`, `iso.png` | v0 renders | deliverables |
| `room_<name>.png` | v0 renders | eye-level room views |

**Rendering in v0.** `viewer.html` uses three.js `GLTFLoader` and `OrbitControls`, vendored from `npm i three` into the project folder (no CDN needed). Browsers block `fetch` of a GLB over `file://`, so run `python -m http.server 8000` in the output folder and have Playwright open `http://localhost:8000/viewer.html` (alternative: inline the GLB as base64 in the page). Wait for a `window.__ready = true` flag set after the model loads before taking a screenshot; this avoids blank captures. Views:
- Top: orthographic camera straight down, ceilings hidden.
- Iso: orthographic at 45 degrees azimuth, about 35 degrees elevation. Dollhouse variant: clip walls at 1.2 m, or hide the two walls facing the camera.
- Room views: for each room polygon, camera at the centroid (nudged inside if concave), eye height 1.6 m, field of view 70 degrees, looking at the polygon vertex farthest from the camera; hide ceilings.
- Lighting: hemisphere light plus one shadow-casting directional light; add a point light per room for later builds.

## Getting accuracy
- **Dimension convention.** Printed dimensions are normally face to face (overall exterior, or interior clear), while the spec holds centrelines. Conversion rule: clear dimension = centreline distance minus the half-thicknesses at both ends (centreline = clear + t for two walls of thickness t); overall exterior = outer centreline extent + t. The checker builds wall faces (the buffered footprint) and compares printed values against room clear widths (from polygonized room polygons) and outer bounding extents, never against raw centreline lengths. Each ref in `scale.refs` declares its `kind` (`outer_face`, `clear`, `centre`).
- **Thickness.** Use the measured value. Snap to a standard (0.10, 0.15, 0.20, 0.30 m) only if within 0.02 m; otherwise keep the measured number (a 0.18 m partition or 0.35 m masonry wall stays as drawn).
- **Orthogonality.** Snap angles within 3 degrees to 0 or 90; snap endpoints within about 0.1 m to one point.
- **Closed rooms.** `shapely.ops.unary_union(wall_lines)` first (this nodes T and X junctions), then `polygonize`. Unclosed rooms yield no polygon, which is the automated alarm.
- **Automatic checks every run:** scale residuals (above), room clear widths and total area against printed values, no opening wider than its wall segment or overlapping another, no zero-area room, every door and window on a wall that exists.

## Risks and failure cases
| Risk | Symptom | Mitigation |
|---|---|---|
| Plan not drawn to scale or wrong label | wrong room sizes | residual gate with defined routes |
| Hatching, furniture, text, grids read as walls | extra walls | OCR text removal, thick-line filter, overlay check |
| Thick walls drawn as two lines or solid fill | doubled or missing walls | close double lines, take centreline, thickness from ink |
| Curved or diagonal walls, bay windows | straight-wall assumption breaks | v0 out of scope; later arc to polyline |
| Door arcs read as walls | curved fragments | detect arcs as door metadata, remove from wall set |
| Skewed or low-res scan | Hough fails | deskew, upscale to 200 dpi or more, or fall back to option A |
| Vision misreads a dimension | plausible wrong scale | cross-check plus overlay |
| Blank viewer page | empty screenshot | serve over HTTP, wait for ready flag; then check software GL speed |
| 3D boolean failure | holes, non-manifold mesh | 2D subtraction in builder A |
| Dataset or model licence | legal limits | check before adopting option C |

## Minimal first version (build today)
Goal: one plan image in; `plan.glb`, `top.png`, `iso.png` and one room view out. A few hours, no Blender, no ML.
1. `pip install pymupdf opencv-python-headless shapely trimesh mapbox-earcut numpy pillow`; `npm i three`.
2. Pick one simple rectilinear plan with a printed overall dimension. Click two pixel points on it and compute px_per_m and origin_px.
3. Have Claude read the image and write `plan.json` in pixel coordinates; run the snap-to-ink script.
4. `overlay.py`: iterate 2 to 4 rounds until it matches.
5. `build.py` (about 150 lines): footprints, opening cuts, leaves, frames, glass, floors, GLB.
6. `viewer.html` plus `shot.py` (http.server, Playwright): top, iso, one room view.
7. Run the checks.

Done criteria: room clear widths and outer extents in the GLB within 2 percent of the printed face-to-face dimensions, every door and window in the right wall with visible leaf or glass, overlay visibly matches the plan.

## Then, in order
1. Automate step 3 with option B on your real plan style (this is where the time goes).
2. Add builder B for Blender renders, textures, furniture placeholders.
3. Second storey, stairs, roofs.
4. Optional AI image polish of a final render, with the original plan beside it as a check on room count and layout.
