# Floor plan to 3D: build plan

## Recommendation

Do not generate the 3D model from the picture. Turn the picture into a small, checkable **JSON plan** that stores points in the plan's own pixel coordinates. Then build the 3D model from that JSON with a deterministic script. Three checks, all automatic except one look at a picture, stand between the image and the model.

## What makes this fail, and what prevents it

| Failure | Prevention |
|---|---|
| AI image generators invent walls and ignore dimensions | No generator in the geometry path. Geometry comes only from the JSON. |
| Scale is wrong | One printed dimension calibrates the scale. Every other printed dimension is a test against it. |
| No registration between the JSON and the image | The JSON stores image pixels. The overlay draws them with no transform. |
| Printed dimensions use inner faces, the model uses centre lines | Every stated dimension declares its basis, and the script converts it. |
| Unprinted positions are guessed by eye | Claude reads coordinates off a labelled pixel grid, and nodes snap to shared lines. |
| Misread rooms go unnoticed | Floors come from the wall network, and each room label must land in exactly one enclosed cell. |
| Viewer renders blank | Serve over localhost. Do not use file://. |
| Unsupported input (curves, scans, photos) | The tool refuses it. See Risks. |

## Assumptions

- Clean, mostly orthogonal plan (PNG, JPG or PDF), one floor, flat roof, straight walls, at least one printed dimension. If none, you supply one measurement.
- Claude in your session can see the image, so no OCR or CV library is needed in v1.
- "3D model" means an orbitable model plus still renders, not BIM or CAD.
- The plan is upright (not rotated). If rotated, deskew once or the tool refuses.
- Internal units are metres.
- Honest dependency list: pip `trimesh shapely numpy pillow mapbox-earcut`; `pdftoppm` (poppler) or `pip install pymupdf` for PDFs; Playwright and Chromium (already installed); npm `three`.

## Pipeline

```
plan.pdf/png --(0) grid.png--> (1) plan.json --(2) checks + overlay.png --> (3) house.glb --> (4) renders/*.png
```

### Step 0: Prepare images
A PDF is rasterised (`pdftoppm -r 200`). `grid.py` writes `grid.png`: the plan with a thin labelled pixel grid every 100 px. Claude reads coordinates from `grid.png`, which is far more reliable than estimating pixels from a bare image. Measurement is still by eye against gridlines, so expect about 1 percent error on unprinted positions. The checks below bound it.

### Step 1: plan.json (pixel coordinates are the source)

```json
{
  "image": "plan.png",
  "wall_height": 2.7,
  "thickness": {"external": 0.25, "internal": 0.10},
  "nodes": {"A":[100,100], "B":[700,100], "C":[700,500], "D":[100,500], "E":[400,100], "F":[400,500]},
  "walls": [ {"id":"w1","a":"A","b":"E","type":"external"},
             {"id":"w2","a":"E","b":"B","type":"external"},
             {"id":"w3","a":"B","b":"C","type":"external"},
             {"id":"w4","a":"C","b":"F","type":"external"},
             {"id":"w5","a":"F","b":"D","type":"external"},
             {"id":"w6","a":"D","b":"A","type":"external"},
             {"id":"w7","a":"E","b":"F","type":"internal"} ],
  "openings": [ {"wall":"w1","type":"door","span":[150,230],"height":2.1,"sill":0},
                {"wall":"w2","type":"window","span":[480,600],"height":1.2,"sill":0.9} ],
  "rooms": [ {"name":"Kitchen","label":[250,300],"floor":"tile"},
             {"name":"Bedroom","label":[550,300],"floor":"wood"} ],
  "stated": [ {"a":"A","b":"B","length":"6.0m","basis":"outer","calibrate":true},
              {"a":"A","b":"E","length":"2.9m","basis":"inner"},
              {"a":"E","b":"B","length":"3.0m","basis":"inner"},
              {"opening":"w1","length":"0.9m"} ]
}
```

Rules:
- **Nodes** are pixel points. Walls reference node ids, so joints are exact by construction. `span` for an opening is two pixel coordinates along its wall, projected onto the wall line.
- **Lengths are unit-tagged strings**, parsed by one function: `12'-6"`, `10ft`, `3200mm`, `3.2m`. A bare number is rejected, so 9'-6" can never be read as 9.6.
- **`stated` entries** span any two nodes (an overall dimension, a chain segment, a room size), or give an opening width. Each declares a `basis`: `inner` (face to face), `centre`, or `outer`. Exactly one entry has `"calibrate": true`. Use the longest printed dimension.
- **Printed room interior sizes** (12'x14') are two `stated` entries across the room's nodes, basis `inner`.

### Step 2: Automatic checks, then one look

`check.py` runs in order and stops at the first failure with a message:

1. **Snap**: nodes within 6 px share an x or y value (walls become exactly orthogonal). Report the largest shift.
2. **Scale**: metres per pixel = calibration length divided by pixel distance, after converting the basis. For a pixel distance `d` between node centre lines, thickness `t`: inner = `d*s - t`, centre = `d*s`, outer = `d*s + t` (with `t` the thickness of the walls at the two ends, halved at each end and summed).
3. **Every other stated dimension** must match within 2 percent or 5 cm, whichever is larger. A chain must also sum to its overall dimension within the same tolerance.
4. **Openings** must lie inside their wall (with 5 cm margin) and must not overlap each other. Stated widths must match.
5. **Rooms**: `shapely.polygonize` over the wall network gives enclosed cells. Each cell must contain exactly one room label, and each label must fall in a cell. The unbounded outside is ignored. Any unlabelled enclosed cell, or two labels in one cell, fails. Floor area per room is printed so you can compare it with any area printed on the plan.

Then `overlay.png`: walls, openings (colour-coded) and room names drawn over the original image, using the pixel coordinates directly. No registration is needed. You look at this one picture. If wrong, tell Claude what is wrong ("the bathroom door is on the east wall") and regenerate the JSON.

### Step 3: build.py makes house.glb

Library: `trimesh`.

1. Convert pixel nodes to metres (scale from Step 2, y flipped).
2. Each wall is a rectangle footprint of its thickness, extended at each end by half the largest thickness at that node. This closes corners and T-junctions even with mixed thicknesses.
3. Each opening splits its wall into pieces: left, right, a block above, and for windows a block below. Extrude each piece with `trimesh.creation.extrude_polygon`. Axis-aligned openings only.
4. Add a thin glass pane per window and a door leaf per door.
5. Floors are the polygonize cells from Step 2, extruded 0.05 m (inner faces only, so floors never poke through walls). Optional ceiling.
6. Materials come from a small table: wood, tile, plaster, glass (flat colours in v1). Name every node (`wall_w1`, `floor_Kitchen`).
7. Export `house.glb`. Write `report.txt`: counts, room areas, and every stated-versus-built dimension.

### Step 4: Viewer and renders

- `npm i three` in the project folder. `viewer.html` imports it from `node_modules` with an import map and loads `house.glb` with `GLTFLoader`.
- **Serve the folder** with `python -m http.server 8000`. Do not open the file from `file://`: Chromium blocks the GLB fetch and module imports there, and the canvas stays blank.
- A Playwright script opens `http://localhost:8000/viewer.html` headless and saves:
  - `top.png`: orthographic top-down.
  - `iso.png`: perspective from a corner at 45 degrees with all materials clipped by a plane at 1.5 m (`renderer.clippingPlanes`). This is a section cut with no facing logic.
  - `room_<name>.png`: camera at `representative_point()` of the room's cell (guaranteed inside the room, even if concave) at 1.6 m, looking at the cell's farthest vertex.
- If the canvas is blank after serving over localhost, launch Chromium with `--use-gl=swiftshader` (software WebGL).

## Outputs

`plan.json` (source of truth), `grid.png`, `overlay.png`, `house.glb`, `report.txt`, `viewer.html`, `renders/top.png`, `renders/iso.png`, `renders/room_*.png`. To change the model, edit the JSON and rerun. No hand editing in a 3D tool.

## Minimal first version (an afternoon)

1. One simple rectangular plan with a printed dimension.
2. Write `grid.py`, then hand-write `plan.json` against `grid.png` (four nodes, four walls, one door, one window, one room).
3. `build.py` with wall pieces, cutouts and the floor, plus the scale and dimension checks.
4. `python -m http.server`, `viewer.html`, and one Playwright screenshot.
5. Add the overlay and the room-cell check.

Done when three different plans go from image to GLB with every stated dimension passing and the overlay approved by eye.

## Later additions (only when v1 exposes a need)

- OpenCV line and contour detection to pre-fill nodes, still passing through the same checks and overlay.
- Tesseract OCR if Claude misreads dimension strings.
- Blender (scripted, or via MCP) importing the GLB for Cycles renders, furniture and a walkthrough video.
- An AI image model for a decorative render, labelled as an illustration and never used as geometry.
- Diagonal and curved walls, stairs, a second storey.

## Risks and failure cases

- **No printed dimensions**: scale cannot be calibrated, so the build refuses until you give one measurement.
- **Scans, hand sketches, photos at an angle, rotated plans**: not supported. The overlay visibly fails.
- **Unprinted positions are measured by eye** from the grid, at about 1 percent. The snap, scale and room-cell checks catch structural errors, not a door placed 15 cm off. The overlay and your eye are the defence.
- **Dimension bases mixed on one plan** (some inner, some outer): declare the basis per entry. A wrong basis shows up as a consistent offset equal to the wall thickness.
- **Symbols misread** (swing arcs, sliding doors, stairs): swing direction is ignored. Openings are cut, not animated.
- **Open-plan spaces with no wall**: polygonize finds no cell, so add an invisible zero-height wall (`"type":"virtual"`) to separate rooms.
- **Columns, balconies, sloped roofs**: not modelled. Columns can be added as boxes.
- **Headless rendering slow or blank**: serve over HTTP, then try software GL, then lower the resolution, or ship the GLB and viewer only.
- **A plausible but wrong reading**: the room-cell check, the area report and the overlay are the defences. Never skip them.
