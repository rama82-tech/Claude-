# Turning a 2D Floor Plan into a 3D Model: Build Plan

## The short answer

Build a small pipeline with one rule at its centre: **the picture is never turned straight into 3D. It is first turned into a plain, human-checkable description of the plan (`plan.json`), and only that file is turned into 3D.**

```
plan image / PDF
   -> 1. rasterize, deskew, set the scale
   -> 2. first guess: walls, doors, windows, rooms (computer vision + Claude's vision)
   -> 3. YOU check and fix the guess on an overlay        <- accuracy comes from this step
   -> plan.json  (single source of truth)
   -> 4. build 3D from plan.json (deterministic code, no AI guessing)
   -> 5. outputs: model.glb, browser viewer, top-down / isometric / eye-level renders
```

Why: a floor plan is only pixels. No tool reads every plan correctly, because drafting styles, scan quality and symbols differ. A pipeline that hides its guesses gives a confident 3D house with a wall in the wrong place. One that shows its guesses and lets you fix them in minutes gives a model you can trust. The 3D step is then short, repeatable code, and a working version of it is included below.

## Assumptions

- You are a builder or designer, not necessarily a 3D or computer-vision specialist. You want something working on your own plans soon.
- One floor per image or PDF page. Mostly straight walls. At least one printed dimension or a known room size. Curved walls, multi-storey stacks and sloped roofs are later phases. Hand sketches and angled photos are out of scope for automated extraction (see risks).
- Wall height is not on a plan. Defaults: 2.7 m walls, doors 0.9 x 2.05 m, window sill 0.9 m and head 2.1 m. All editable.
- "3D model" means a shareable GLB file, something you can orbit in a browser, and rendered images. Not CAD or BIM (no IFC in v1).
- Environment: your Claude Code cloud session (Linux, Python 3.13 here, Node, Chromium and Playwright, no GPU). I checked that `pip install trimesh shapely numpy mapbox_earcut` works in a fresh venv here. I could not find a `bpy` wheel for this Python, so Blender is treated as optional (see Phase 2).

## The `plan.json` format (the contract everything depends on)

Coordinate frame, fixed once: **metres; X east, Y north, Z up.** Image rows run top to bottom, so the Y flip (`y_m = (img_h_px - row) / scale_px_per_m`) happens once, at ingest. After ingest, shift everything so the plan's minimum corner is (0,0). No other module touches pixels.

```json
{
  "version": 1,
  "wall_height": 2.7,
  "source": {
    "image": "plan.png",
    "scale_px_per_m": 118.1,
    "scale_status": "verified | single-source | assumed",
    "scale_from": "dimension 12'-6\" between w1 ends"
  },
  "walls": [
    {"id": "w1", "a": [0, 0], "b": [5, 0], "t": 0.20, "kind": "exterior"},
    {"id": "w5", "a": [2.5, 0], "b": [2.5, 4], "t": 0.10, "kind": "interior"}
  ],
  "openings": [
    {"id": "d1", "wall": "w1", "type": "door",   "at": 1.2, "width": 0.9, "sill": 0.0, "head": 2.05},
    {"id": "n1", "wall": "w3", "type": "window", "at": 3.5, "width": 1.2, "sill": 0.9, "head": 2.1}
  ],
  "rooms": [
    {"name": "Kitchen", "label_at": [1.2, 2.0], "floor": "tile",
     "printed": {"w": 2.35, "d": 3.8, "basis": "clear"}}
  ]
}
```

Rules:
- **Walls are centrelines** (`a` to `b`) plus thickness `t`. Corners and T-junctions are formed by unioning the thickened lines, so wall ends sit on the other wall's centreline.
- **An opening belongs to one wall** by id. `at` is the distance in metres from the wall's `a` end to the opening's centre. Openings must sit at least `t/2` from either end of the wall; the build refuses otherwise and says which one.
- **Rooms are derived, not drawn.** The code polygonizes the wall centrelines; `label_at` (a point inside the room) links a name and material to the polygon. `printed` is the number on the drawing, with `basis` saying whether it is a clear interior size or a centreline size.
- Everything the pipeline guessed that you did not confirm carries `"confirmed": false`, and the overlay shows it in a different colour.

## Tools and why each earns its place

| Job | Tool | Why |
|---|---|---|
| Rasterize PDF, clean image | `pymupdf`, `Pillow` | Pure pip, no system packages |
| Deskew, threshold, thick-line detection | `opencv-python-headless` | Walls are the thickest dark strokes; morphology separates them from dimension lines and furniture |
| 2D geometry (snap, union, cut, rooms) | `shapely` | Wall union, opening cutters, `polygonize` for rooms |
| Dimensions and labels | Claude's own image reading first; `pytesseract` as a cross-check | Plan text is small and rotated; vision reads it better, a second reader catches errors |
| Doors and windows | Claude vision on cropped tiles plus the geometric clue (a gap or thinner double line in a wall) | Symbols vary by drafter |
| Optional trained detector | CubiCasa5k-style segmentation models | Phase 3 only: heavy setup, still needs your check |
| 3D geometry and GLB export | `trimesh` + `numpy` + `mapbox_earcut` | Extrudes 2D polygons; no Blender needed |
| Browser view | `three.js` (pinned, vendored locally) | One page, runs on a phone |
| Preview images | Playwright screenshots, with a matplotlib fallback | Already installed |
| Photoreal renders (optional) | Blender headless | Better light and materials; not on the critical path |

Not the core: an AI image generator ("make this plan 3D"). It produces pretty pictures with invented walls and wrong sizes. It has one legitimate use, mood images in the last phase. Live Blender through MCP is good for hands-on tweaking, but headless scripts are easier to repeat; use MCP only if you want interactive editing.

## The pipeline, step by step

### Step 1. Scale (the step that decides all accuracy)

1. PDF: render at 300 dpi. Photo or scan: deskew by the dominant line angle, crop the border.
2. Get `scale_px_per_m` from the best source available, and record which one:
   - two points at the ends of a printed dimension, with its number (best);
   - a drawn scale bar;
   - a known object, a standard door of about 0.9 m (weakest).
3. Set `scale_status`:
   - **verified**: two independent measurements (different walls) agree within 2 percent.
   - **single-source**: only one dimension exists. The build proceeds, the overlay and every render are stamped "scale unverified", and the user is asked to check one real-world dimension (a room width they know) before trusting sizes.
   - **assumed**: only the door fallback. Build proceeds with a loud banner; sizes are approximate.
   - Two measurements that disagree by more than 2 percent block the build until resolved. That catches the classic "house 15 percent too small" error.

### Step 2. First-guess extraction

- **Walls:** binarize, apply a morphological opening about one wall-width wide to keep thick strokes, skeletonize, trace centrelines, snap endpoints within about half a wall thickness, and snap to exact horizontal or vertical only when within 3 degrees. Measure thickness per wall; exterior and interior differ.
- **CAD-style double-line walls:** detect the style first. Fill the gap between parallel lines rather than measuring stroke thickness.
- **Openings:** look for gaps in wall lines and door arcs; classify as door, window or open archway; record width and the `at` position along the wall. Claude vision on a crop settles the doubtful ones.
- **Rooms:** `shapely.polygonize` the centrelines; attach label text by position.
- **Dimension text:** keep every printed string as a `printed` value to compare in Step 3.

### Step 3. Human check

Produce `check.png`: the original image with walls in red, doors green, windows blue, unconfirmed items dashed, each room named with its measured **clear** size.

**What is compared to what.** Printed room sizes are normally clear interior sizes. Centreline polygons are larger by about one wall thickness (a 3.0 m clear room with 0.2 m walls measures 3.2 m on centrelines, a false 6.7 percent error). So the check compares the printed value against the room polygon with the wall bodies removed (`clear_size()` in the code below), unless `basis` says "centreline". A mismatch above 3 percent after that correction is flagged.

Fix problems by editing `plan.json` (short and readable) or by telling Claude "the hall wall is missing; the bathroom door is on the east wall, 0.8 m wide". It updates the file and redraws. Expect 1-3 rounds on a clean plan, more on a messy scan.

### Step 4. Build the 3D from `plan.json`

Openings are cut **in 2D, before extrusion**, so no 3D boolean library is needed:

1. Union the thickened centreline of every wall into one footprint.
2. For each opening, make a cutter rectangle along its wall (a hair thicker than the wall) and subtract all cutters from the footprint. Extrude the result to wall height.
3. Add back what remains above and below each opening: a lintel from `head` to wall height and, for windows, a sill block from 0 to `sill`, each extruded from the cutter-and-wall overlap. Windows also get a thin glass pane.
4. Floors: union of the polygonized rooms, a 0.1 m slab below Z=0. Ceiling optional (off for cutaways).
5. Materials by room name or `floor` field; defaults are listed in the output.
6. Axes: plan is Z-up; glTF is Y-up. Apply a -90 degree rotation about X on export, or the model lies on its side in every viewer. Plan north (+Y) ends up as -Z in glTF, which the viewer's camera presets account for.

Reference implementation (tested here on a 5 m by 4 m two-room plan with two doors and a window; it exports a GLB and reports clear room sizes of 2.35 by 3.80 m for 2.5 m centreline bays):

```python
# plan_to_3d.py   pip install trimesh shapely numpy mapbox_earcut
import json, sys
import numpy as np, trimesh
from shapely.geometry import LineString
from shapely.ops import unary_union, polygonize

def wall_poly(w):
    return LineString([w["a"], w["b"]]).buffer(w["t"] / 2, cap_style=2, join_style=2)

def opening_box(w, o):
    (ax, ay), (bx, by) = w["a"], w["b"]
    L = float(np.hypot(bx - ax, by - ay)); ux, uy = (bx - ax) / L, (by - ay) / L
    c0, c1 = o["at"] - o["width"] / 2, o["at"] + o["width"] / 2
    if c0 < w["t"] / 2 or c1 > L - w["t"] / 2:
        raise ValueError(f'{o["id"]}: too close to the wall end; move it or lengthen the wall')
    seg = [(ax + ux * c0, ay + uy * c0), (ax + ux * c1, ay + uy * c1)]
    return LineString(seg).buffer(w["t"] / 2 + 0.001, cap_style=2)

def extrude(poly, z0, z1):
    out = []
    for p in (poly.geoms if hasattr(poly, "geoms") else [poly]):
        if p.is_empty or p.area < 1e-6: continue
        m = trimesh.creation.extrude_polygon(p, z1 - z0)
        m.apply_translation([0, 0, z0]); out.append(m)
    return out

def build(plan):
    H = plan.get("wall_height", 2.7)
    walls = {w["id"]: w for w in plan["walls"]}
    solid = unary_union([wall_poly(w) for w in walls.values()])
    cutters, pieces = [], []
    for o in plan.get("openings", []):
        w = walls[o["wall"]]; cb = opening_box(w, o); cutters.append(cb)
        sill, head = o.get("sill", 0.0), o.get("head", 2.05)
        foot = cb.intersection(wall_poly(w))
        if sill > 0: pieces += extrude(foot, 0, sill)
        if head < H: pieces += extrude(foot, head, H)
        if o["type"] == "window":   # thin glass pane in the middle of the opening
            pieces += extrude(foot.buffer(-w["t"] / 2 + 0.01, join_style=2), sill, head)
    shell = solid.difference(unary_union(cutters)) if cutters else solid
    meshes = extrude(shell, 0, H) + pieces
    rooms = list(polygonize(unary_union([LineString([w["a"], w["b"]]) for w in walls.values()])))
    meshes += extrude(unary_union(rooms), -0.1, 0)          # floor slab
    scene = trimesh.Scene()
    for i, m in enumerate(meshes): scene.add_geometry(m, node_name=f"part{i}")
    return scene, rooms

def clear_size(room, walls):
    # printed sizes are usually CLEAR interior sizes: remove the wall bodies from the centreline polygon
    r = room.difference(unary_union([wall_poly(w) for w in walls]))
    x0, y0, x1, y1 = r.bounds; return x1 - x0, y1 - y0, r.area

if __name__ == "__main__":
    plan = json.load(open(sys.argv[1]))
    scene, rooms = build(plan)
    # Z-up (plan) -> Y-up (glTF)
    scene.apply_transform(trimesh.transformations.rotation_matrix(-np.pi / 2, [1, 0, 0]))
    scene.export(sys.argv[2])
    for r in rooms: print("room", [round(v, 2) for v in clear_size(r, plan["walls"])])
```

Known limits of this reference code: one uniform grey material (per-room colours come next: split the floor per room and add a `trimesh.visual.material.PBRMaterial`); no frames; a door placed across a wall junction is not handled (the check above refuses openings too near a wall end); it treats walls as straight segments.

### Step 5. Outputs

| File | What it is | Needs |
|---|---|---|
| `plan.json` | The checked description of the plan | nothing |
| `check.png` | The overlay used for checking | OpenCV or matplotlib |
| `model.glb` | The 3D model; opens in Blender, three.js, Windows 3D Viewer, macOS Quick Look | trimesh |
| `viewer.html` | Orbit viewer | pinned three.js, served over HTTP |
| `render_topdown.png`, `render_iso.png`, `render_room_*.png` | Top-down, isometric cutaway, eye-level per room | Playwright (v1) or Blender (v2) |
| `topdown_fallback.png` | Flat top-down drawing of walls, openings and rooms | matplotlib only; works with no WebGL |
| `house.blend`, `walkthrough.mp4` | Editable scene; camera path | Blender (optional, later) |

#### Making the viewer and screenshots actually work

- **Do not open `viewer.html` from `file://`.** The GLB fetch is blocked. Either run `python -m http.server 8000` in the output folder and open `http://localhost:8000/viewer.html`, or embed the GLB in the page as a base64 data URL.
- **Pin and vendor three.js** (for example `npm i three@0.160.0`, copy `three.module.js`, `GLTFLoader.js`, `OrbitControls.js` into the folder). Do not rely on a CDN; the session network may not allow it.
- **Lights live in the viewer**, not in the GLB: add a hemisphere light, one directional light, and enable shadows. The GLB carries geometry and materials only.
- **Camera presets** in the page: `top` (orthographic camera above, looking down -Y in glTF terms, ceiling hidden), `iso` (orthographic at 45 degrees azimuth, 35 degrees elevation, ceiling hidden), `eye` (perspective at 1.6 m, placed at each room's `label_at`).
- **Headless Chromium without a GPU** needs software GL. Launch Playwright with `args=["--use-angle=swiftshader", "--enable-unsafe-swiftshader", "--ignore-gpu-blocklist"]` and wait for a `window.__ready` flag your page sets after the GLB has loaded. These flags vary by Chromium version, so test a blank page rendering a cube first (two minutes); if it still fails, use `topdown_fallback.png` and move on.

## How to get each element accurate

- **Walls:** at 300 dpi on a 24x36 in sheet, one pixel is about 2 mm, far finer than needed. The real error source is wrong scale, hence Step 1. Keep real angles when a wall is more than 3 degrees off square.
- **Thickness:** measured per wall type, not assumed.
- **Doors and windows:** width and position from the symbol; heights default unless a schedule or elevation exists. Swing direction is cosmetic in v1.
- **Floors and rooms:** closed polygons only. A room that will not close gets an "open here" marker on the overlay; the pipeline never invents a wall.
- **Materials:** the plan rarely says. Defaults by room name (tile for bath and kitchen, wood elsewhere), overridable per room (`"floor": "oak"`).
- **Lighting:** the thing that makes renders feel real. Soft shadows, a warm sun at a fixed angle, windows that are real openings with glass. Otherwise interiors render black.

## Phased build

### Version 1: one afternoon, no computer vision, no Blender

1. Copy the schema above. Give Claude your plan image; it reads walls, openings and dimensions into `plan.json` (about 20 walls for a small flat; the example above is 5 walls, 3 openings).
2. Run `python plan_to_3d.py plan.json model.glb`. It prints the clear size of each room; compare with the drawing.
3. `check.py` (about 40 lines of matplotlib): draw the walls and openings from `plan.json` over the original image after applying the scale. If the picture does not line up, the JSON is wrong, not the code.
4. `viewer.html` plus a Playwright script for one top-down and one isometric screenshot, or `topdown_fallback.png` if WebGL will not start.

Done when: each room's clear size matches the printed size within 2 percent (or the scale is marked unverified and says so), every door and window is a real hole you can see through, and the GLB opens in an outside viewer.

### Version 2: automate the first guess and improve renders

- OpenCV wall extraction, gap-based openings, shapely rooms, dimension reading. Success measure: on 5 of your own plans, how many edits does each need?
- **Blender, optional.** First probe it in 5 minutes: `pip download bpy` (this container's Python 3.13 found no wheel), or download a Linux tarball from blender.org and run `blender -b --version`, if the network allows that host. If it installs, write `build_blender.py` that reads `plan.json` itself (or imports `model.glb`) and then adds lights, per-room materials and cameras; the GLB has none. Expect Cycles on CPU to take minutes per image at 1280x720 with about 64 samples and denoising; EEVEE usually needs a GPU or software GL. If Blender will not install, v1's viewer renders remain the deliverable.

### Version 3: polish and breadth

Multiple levels, stairs, curved walls, furniture library, walkthrough video, an optional trained segmentation model for hard scans, a small web upload page.

### Version 4 (optional): style images

Feed a render as a structural reference to an image generator for a mood picture. Label it as artwork, not measurement.

## Risks and failure cases

| Risk | What it looks like | What to do |
|---|---|---|
| Wrong scale | House 15 percent too small | Scale status (verified / single-source / assumed); two disagreeing measurements block the build |
| Single dimension only | Nothing to cross-check | Build, stamp "scale unverified", ask for one known real-world dimension |
| Clear vs centreline confusion | Correct model flagged as 6 percent wrong | Compare clear sizes; record `basis` for each printed number |
| Furniture, text, hatching read as walls | Short extra walls | Filter by thickness and length; overlay shows them; delete in the JSON |
| Thin-line CAD walls | Walls not detected | Detect style first; fill between parallel pairs |
| Low-res or skewed scans | Wobbly lines | Deskew; require about 150 dpi or better; scale snap tolerances to wall width |
| Door vs window confusion | Window cut as a door | Vision check on crops; unconfirmed items shown dashed |
| Opening near a wall end or junction | Build error | The code refuses and names the opening; move it or split the wall |
| Unclosed rooms | No floor, odd area | List the gaps; never auto-invent walls |
| Hand sketches and photos | Curved, uneven lines | Out of scope for automation; use the manual JSON route |
| Wrong axes | Model on its side or mirrored | Fixed frame (X east, Y north, Z up), single Y flip at ingest, one -90 degree X rotation on export |
| Blank browser render | Empty screenshot | Serve over HTTP, vendored three.js, swiftshader flags, ready flag; fall back to the matplotlib top-down |
| Blender will not install | No photoreal renders | Optional by design; v1 deliverables do not depend on it |
| Missing facts (ceiling height, sill, materials) | Invented values | Defaults are written into `plan.json` and shown in the output |
| Over-trusting an AI | Confident but wrong model | The check step is mandatory |
| Privacy of plans | Client documents | Process in the session; do not send plans to third-party generators without the owner's consent |

## How to know it worked

1. **Rectangle:** 5 m by 4 m room, four 0.2 m walls, one door. Centreline area 20 m2; clear 4.8 by 3.8 m.
2. **L-shape plus an interior wall:** no gaps or doubled faces at corners and T-junctions.
3. **Openings:** the screenshot shows light through the window and a visible doorway; try to place an opening at a wall end and confirm the refusal.
4. **Your plan:** each room's clear size within 2-3 percent of its printed size.
5. **Axes:** open `model.glb` in an outside viewer; it stands upright and north is where the plan says.
