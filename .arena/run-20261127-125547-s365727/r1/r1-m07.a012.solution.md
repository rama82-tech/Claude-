# Turning a 2D floor plan into a 3D model: build plan

## 1. Recommendation in one paragraph

Do not go straight from picture to 3D. Go **picture -> a small, human-checkable JSON description of the plan ("plan IR": walls, openings, footprint, rooms, in metres) -> 3D**. Every 3D output (a three.js viewer, a `.glb` file, later Blender renders) is generated from that one JSON file. That is what makes the walls accurate: you can inspect and fix the JSON, which you cannot do with pixels or with an AI-generated image. Computer vision proposes the geometry; Claude (reading the plan image inside your Claude Code session) supplies what CV is bad at (room names, door versus window, printed dimension text); an overlay image lets you check the result in seconds. The minimal first version in section 9 was built and run in this container on synthetic plans (an L-shaped plan with piers, a door near a corner, an open hall gap, solid and double-line wall styles). It has not been run on a real architect's plan, and section 8 lists where I expect it to fail.

## 2. Assumptions (nothing was stated, so I chose these)

1. Input is a **clean architectural plan** (CAD/PDF export or good scan), one storey, one image per floor. Hand sketches and photos of paper are Phase 3.
2. Walls are **axis-aligned** in the MVP. Diagonal and curved walls are Phase 2.
3. The plan has a **known scale**: a printed dimension, a scale bar, or one length you can type in. Without scale there is no true 3D size, so the script refuses to run without `--ppm` or `--dim`.
4. "3D model" means an explorable model plus standard files (`.glb`, later `.blend`) and still renders (top-down, perspective, later eye-level). Not a BIM/IFC model with structure and services (an extension).
5. Defaults when the plan says nothing: ceiling 2.7 m, door height 2.05 m, window sill 0.9 m and height 1.2 m. Defaulted openings carry `"confidence": "low"`.
6. You work in this cloud container (Linux, Python, Node, headless Chromium), with outbound traffic through a proxy that allows only some hosts.
7. "Claude reads the image" means the Claude Code session itself looking at `overlay.png` and `crops/*.png` (image files can be opened by the session). No separate API key is assumed. If you later want this unattended, the same prompt can be sent through the Anthropic API; that variant is untested here.

## 4. Options considered

Scores 1 (poor) to 5 (good). Criteria: **Acc** dimensional accuracy; **Open** doors/windows/semantics; **MVP** speed to a first working version; **Here** works in this container as verified in section 3; **Out** editable, standard output files; **Look** ceiling on visual quality; **Per-plan** effort for each additional plan. Scores are my judgement, not measurements.

| Option | Acc | Open | MVP | Here | Out | Look | Per-plan | Total |
|---|---|---|---|---|---|---|---|---|
| A. AI image generator turns the plan into a "3D render" (img2img) | 1 | 1 | 5 | 2 | 1 | 4 | 5 | 19 |
| B. Fully automatic CV -> three.js, no human step | 3 | 2 | 4 | 5 | 4 | 3 | 5 | 26 |
| C. **CV + vision LLM propose a JSON, overlay check, JSON -> three.js/glTF now, Blender later** | 5 | 4 | 3 | 5 | 5 | 4 | 4 | **30** |
| D. Pretrained deep floor-plan segmentation (CubiCasa5K-style), then vectorize | 3 | 3 | 1 | 2 | 4 | 3 | 4 | 20 |
| E. Fully manual tracing in a browser (click corners, type widths) | 5 | 5 | 4 | 5 | 5 | 3 | 2 | 29 |
| F. Same as C but Blender (bpy) as the only backend | 4 | 4 | 2 | 2 | 5 | 5 | 3 | 25 |

Why C: A cannot be trusted for geometry (image generators redraw walls, change sizes and invent furniture; fine as an optional mood picture, never as the model). D needs model weights, ideally a GPU, and a licence check (verify the dataset terms before building on it), and still outputs raster masks. B has no place to catch errors, so a wrong wall ships silently. E is accurate but slow per room, so it is the **fallback editing mode inside C**. F looks best but is the least runnable here today; because everything hangs off the JSON, Blender becomes a second exporter in Phase 2. C, E and F are close, so the matrix ranks risk rather than measuring it; the tie-breaker is "works in this container today and improves per plan".

## 5. Architecture

```
 plan.png / .pdf / scan
        |
 [0] normalise: PDF -> PNG (or vector extraction), deskew, crop, scale from --dim
        |
 [1] plan2ir.py (OpenCV): remove text -> wall bars -> gaps = openings; flood fill -> footprint + rooms
        |                  writes plan.json + overlay.png + crops/ + grid.png + warnings
 [2] semantics (Claude reads overlay.png and crops/): door/window types, room names -> semantics.json
        |                  apply_semantics.py validates counts, patches plan.json
        v
   plan.json   <-- single source of truth (metres, y down like the image)
        |   ^
        |   +-- [3] you review overlay.png + warnings, edit JSON, re-run only the 3D step
        |
   +----+---------------------+-------------------------+
   v                          v                         v
 viewer.html (three.js)   model.glb (GLTFExporter)   Blender bpy (Phase 2)
 + Playwright PNGs        opens anywhere             model.blend, Cycles, walkthrough
```

### The plan IR (`plan.json`), as actually written by the MVP

```json
{
  "units": "m", "height": 2.7, "source": "plan.png", "style": "solid",
  "scale": {"method": "dim", "ppm": 100.0, "check_error_pct": 0.0},
  "walls":    [{"id": "w0", "a": [1.2, 1.2], "b": [9.2, 1.2], "t": 0.15, "h": 2.7}],
  "openings": [{"id": "o0_0", "wall": "w0", "type": "window", "offset": 1.185, "width": 1.19,
                "sill": 0.9, "height": 1.2, "confidence": "vision"}],
  "gaps":     [{"from": [5.41, 3.22], "o": "v", "width": 1.49, "hint": "left open (no wall) ..."}],
  "floor":    [[[1.13, 1.13], [1.13, 6.29], [6.29, 6.29], [6.3, 4.29], [9.29, 4.29], [9.29, 1.13]]],
  "rooms":    [{"id": "r0", "name": "Living", "area_m2": 31.25, "polygon": [[...]], "floor": "oak", "label_px": [455, 360]}],
  "footprint_area_m2": 36.1,
  "warnings": []
}
```
`a`/`b` are a wall's centreline ends, `t` its thickness, `offset` the distance from `a` along the wall to the opening's centre. Wall coordinates include the image margin (the viewer recentres); subtract the margin if you need origin-at-corner.

## 6. Step-by-step pipeline and how each accuracy problem is handled

**Step 0. Normalise and calibrate scale (decides all accuracy).**
- Raster: PDF -> PNG at 300 dpi with `pymupdf` (`page.get_pixmap(dpi=300)`); crop to the drawing.
- Vector PDFs: if the PDF is a CAD export, its lines are real vectors. `page.get_drawings()` returns line and rectangle items with exact coordinates; keep the long axis-aligned ones, and pair double lines closer than 0.35 m into one wall. I did not write or test this path; plan2ir.py on a 300 dpi raster is the tested route, and vector extraction is a Phase 2 item (it removes the pixel measurement error, not the semantic work).
- Reading pixel positions: run `plan2ir.py plan.png --grid`; it writes `grid.png` with a labelled 100 px grid. Open it, read the pixel x/y of the two ends of a printed dimension (about +/-5 px by eye, so use a long dimension: 5 px on 600 px is under 1%), and pass `--dim x1,y1,x2,y2,metres`. This yields `ppm`. Scale priority: (1) a printed dimension, (2) a scale bar, (3) one typed-in wall length, (4) a standard door leaf of about 0.9 m, as sanity check only.
- Cross-check: pass every other printed dimension as `--check x1,y1,x2,y2,metres` (repeatable). The worst error goes to `scale.check_error_pct` and a warning fires above 2%. This proves the drawing scales uniformly; it does not by itself prove the extracted walls match, which is what the overlay is for.
- Deskew: if walls are not axis-aligned, rotate first (dominant angle from Hough lines or `cv2.minAreaRect` on the wall mask). Not in the MVP.

**Step 1. Walls.** Binarise (Otsu). Delete connected blobs smaller than 0.3 m in both directions (letters, ticks, symbols) before anything else. Open with a kernel of the thinnest real wall (`--wall-min`, 0.08 m) to remove lines thinner than a wall, then open with long 1-pixel kernels (`--min-len`, 0.25 m) to keep horizontal and vertical bars. Each bar gives centreline and thickness. `--style hollow` first closes the mask with `--wall-max` (0.35 m) so walls drawn as two parallel lines fill in; `--style auto` (default) tries solid and retries hollow if no walls are found. Piers and corner stubs down to 0.25 m survive.

**Step 2. Openings.** Collinear bars in the same line are grouped. A gap between consecutive bars is classified by width: under 0.4 m = glitch, joined with a warning; 0.4 m to `--max-hole` (1.3 m) = opening, wall merged and a hole recorded; over 1.3 m = **left open** (no wall, no lintel) and listed under `gaps`, because a wide gap in an interior partition is usually a cased opening or open-plan link, and a hole with a lintel there is wrong. Cost of that choice: a genuine 1.8 m window in an outer wall is left open until you re-run with `--max-hole 2.4`; the `gaps` hint says so, and the overlay draws gaps in orange. Opening type (door or window) cannot be decided from a gap, so every opening starts as `door`, confidence `low`, until step 2b.

**Step 2b. Semantics (Claude reads images).** See section 7 for the exact protocol and the validation rule.

**Step 3. Footprint and rooms.** Wall rectangles are rasterised from the IR; wide gaps are sealed in a separate mask used only for the outside test. Flood fill from the image border marks the exterior; everything else is the footprint. Its outer contour, simplified at 0.03 m, is the floor slab (`floor`), so L-shapes and notches are correct. Rooms are the connected interior regions of the footprint minus walls (at least 1 m2); each gets an id, area and polygon, and the overlay prints the id so names can be attached by id. Limit: an enclosed courtyard cannot be told from a room.

**Step 4. Validate (reported, never fixed).** `plan2ir.py` prints and stores warnings for: a wall end that touches no perpendicular wall and is not next to a wide gap ("free end"); walls under 0.3 m; openings wider than 85% of their wall; joined cracks; no closed room (outline not closed); worst scale-check error over 2%; footprint area more than 5% away from `--area` (note a printed area is often interior and the footprint is measured to outer faces, so expect a gap). `overlay.png` draws walls red, openings blue with ids, wide gaps orange, rooms tinted with ids, on top of the source image.

**Step 5. Build the 3D (geometry rules).**
- Each wall is a rectangle `length x height` in its own vertical plane with one rectangular hole per opening, extruded by the thickness.
- Coordinates: plan `(x, y)` -> world `(x, 0, y)`, plan y down maps to +z. The top camera is a true `OrthographicCamera` above the plan centre with `up = (0,0,-1)`, which puts plan y down the screen exactly like the image, so nothing is mirrored (verified: the notch of the L appears at the bottom right in both the plan and the render). Mirroring is the most common silent bug in this kind of project.
- Corners: bars already include the corner squares. For hand-drawn walls, extend each end by `t/2` at T and L joints.
- Floor: one slab per footprint polygon, and a thin (3 mm) room polygon on top coloured by the room's `floor` material.
- Door leaves, window glass, ceilings: Phase 2.

**Step 6. Materials.** MVP: plain PBR colours with a floor table (`oak`, `tile`, `concrete`) selected by the room's `floor` field. Map room names to finishes through a small table, never let an AI generator pick per wall, so renders are reproducible. Textures (CC0 sets) in Phase 2, after checking proxy access.

**Step 7. Lighting and cameras.** MVP: hemisphere light plus one shadow-casting directional light aimed at the plan centre, shadow frustum scaled to the plan span (a default frustum of about 10 m clips shadows on a 12 m house). The top view switches shadows off, because wall shadows darkened the floor in my first test render. Phase 2 in Blender: sun and sky, an area light per window placed from the openings list, Cycles with denoising for stills, eye-level cameras at 1.6 m per room.

**Step 8. Export.**

| File | Made by | Use |
|---|---|---|
| `plan.json` | `plan2ir.py` + your edits + `apply_semantics.py` | source of truth, diffable in git |
| `overlay.png`, `crops/*.png`, `grid.png` | `plan2ir.py` | verification and the images Claude reads |
| `model.glb` | three.js GLTFExporter via `render.mjs` | opens in Blender, Windows 3D viewer, Quick Look, web |
| `render_persp.png`, `render_top.png` | `render.mjs` (Playwright) | client images |
| `viewer.html` | MVP | explorable model; serve over http, not `file://` |
| per-room eye-level renders, `model.blend`, `walkthrough.mp4` | Blender, Phase 2 | not in the MVP |

## 7. Where a vision LLM and where CV are used (concrete protocol)

CV gives coordinates and thicknesses (exact to a pixel). Claude gives meaning. Do not trust an LLM's pixel coordinates; ask for labels, counts and ids only, then validate.

Protocol, run inside the Claude Code session after `plan2ir.py`:
1. Claude opens `overlay.png`, then each `crops/<id>.png` (3 m square around each opening, enlarged to at least 300 px) and the original plan.
2. Prompt used (copy as is): *"Plan image, overlay, and crops attached. Count the door symbols and the window symbols in the whole plan. For each opening id, say door or window (a door shows a swing arc or leaf line; a window shows two or three thin parallel lines across the wall). For each room id, give the name printed in it, if any. Read any printed window sizes such as W1200x1500. Answer only with JSON of this shape: {"counts": {"doors": n, "windows": n}, "openings": {"o0_0": {"type": "window", "sill": 0.9, "height": 1.2}}, "rooms": {"r0": {"name": "Living", "floor": "oak"}}}. If unsure about an item, omit it."*
3. Save the answer as `semantics.json`, run `python apply_semantics.py plan.json semantics.json`.
4. Validation rule ("counts match"): doors + windows counted in the image must lie between the number of extractor openings and openings plus open gaps (wide gaps can be windows or doors too); and the per-opening types must not exceed the counted doors and windows. If either fails, **no opening type is applied** (room names still are) and you review the crops by hand, or use `--force`. I tested a passing and a failing file (a file counting 3 openings against 4 found was refused).
5. What is not validated: that each individual door/window label is right. The crops make that a ten-second visual check per opening. I did not measure how accurate Claude is at this on real plans. If it is poor, the fallback is exactly the manual edit of `type`, and nothing else in the pipeline changes.

## 8. Risks and failure cases

| Failure case | What goes wrong | Mitigation |
|---|---|---|
| No or wrong scale | Everything wrong-sized but plausible | Script refuses without `--ppm`/`--dim`; `--check` 2% rule; a wrong ppm usually gives "0 walls found" or absurd opening widths |
| Scan skew / photo perspective | Walls not parallel, non-uniform scale | Deskew; photos need a 4-point homography; Phase 3 |
| Double-line (hollow) walls | Nothing found in solid mode | `--style hollow` (tested on synthetic); window symbols drawn inside a gap fill the gap in hollow mode, so those windows are missed: add by hand |
| Hatched or poche walls | Hatch lines thinner than `--wall-min` vanish | try `--style hollow`, or fill the poche in the PDF; untested on real hatch |
| Heavy furniture or fixtures drawn thick | False walls | overlay review, delete from JSON; free-end warnings help |
| Thin partitions below `--wall-min` | Walls missing | lower `--wall-min`; overlay shows the miss |
| Window piers, corner stubs | Previously dropped, causing missed openings | now kept down to 0.25 m (tested); anything under 0.25 m is dropped silently apart from a free-end warning |
| Wide gap in an exterior wall (large window) | Left open instead of a window | listed under `gaps`; re-run with `--max-hole`; footprint is unaffected (gaps are sealed for the outside test) |
| Hall opening 1.0 to 1.3 m between partition stubs | Becomes a door hole with lintel | review the crops and edit the opening's `height` or delete it; ambiguity is inherent |
| Door drawn open with no gap | Missing door | swing-arc check by Claude on the overlay; not automated |
| Diagonal or curved walls | Dropped | out of scope; Phase 2 |
| Stairs, columns, balconies, sloped ceilings, double height | Not representable | unsupported; placeholders Phase 3 |
| Several floors on one sheet | Merged garbage | crop manually first |
| Courtyard enclosed by walls | Floored as if inside | edit `floor` polygon |
| Browser cannot load libraries (CDNs blocked here) | Blank page | local `node_modules` (done); `file://` fetch also blocked, so use the http server in `render.mjs` |
| Playwright wants a different Chromium than installed | `launch()` fails | `CHROMIUM_PATH` as in section 9 |
| Software GL slow and noisy | Slow shadows | small scenes; Cycles later |
| Confidential plans sent to external services | Leak | keep processing local; external image APIs only with permission |
| AI picture shown as if it were the model | Misleading sizes | label "illustration, not to scale" |

## 9. The minimal first version (runnable now)

Time to build: about half a day with your own plan. Folder `plan3d/`. Put the five files below in it (`gen_test.py` is optional: it makes the test plan I used).

```bash
mkdir plan3d && cd plan3d
python3 -m venv v && ./v/bin/pip install opencv-python-headless numpy pillow
npm init -y && npm i three@0.160.0 playwright          # then use the installed Chromium, see below
python3 gen_test.py                                    # optional: writes plan.png (test L-plan; "hollow" argument = double-line walls)
./v/bin/python plan2ir.py plan.png --grid              # 1. writes grid.png; read the pixel ends of a printed dimension from it
./v/bin/python plan2ir.py plan.png --dim 120,40,920,40,8.0 --check 120,40,920,40,8.0   # 2. writes plan.json, overlay.png, crops/
# 3. open overlay.png and read the warnings; in the Claude Code session, run the section 7 protocol -> semantics.json
./v/bin/python apply_semantics.py plan.json semantics.json
CHROMIUM_PATH=/opt/pw-browsers/chromium-1243/chrome-linux64/chrome node render.mjs   # writes render_persp.png, render_top.png, model.glb
```
(In another container, if `npx playwright install chromium` works, omit `CHROMIUM_PATH`.) With your own plan use `--ppm N` instead of `--dim` if you already know pixels per metre.

Flags you will touch: `--style auto|solid|hollow`, `--max-hole` (default 1.3 m), `--min-len` (0.25 m), `--wall-min` (0.08 m), `--wall-max` (0.35 m), `--area`, `--height`.

### `plan2ir.py` (tested on the synthetic plans)

```python
#!/usr/bin/env python3
"""plan2ir.py  plan.png (--ppm N | --dim x1,y1,x2,y2,metres) [options]
Axis-aligned walls, openings, footprint and rooms from a raster floor plan.
Writes plan.json (metres, y down like the image), overlay.png, grid.png, crops/<opening>.png.
Never auto-fixes: everything doubtful goes into plan.json "warnings" and "gaps"."""
import argparse, json, math, os, sys
import cv2, numpy as np

ap = argparse.ArgumentParser()
ap.add_argument("image")
ap.add_argument("--ppm", type=float, help="pixels per metre")
ap.add_argument("--dim", help="x1,y1,x2,y2,metres : two pixel points on a printed dimension -> ppm")
ap.add_argument("--check", action="append", default=[], help="x1,y1,x2,y2,metres : another printed dimension; repeatable")
ap.add_argument("--area", type=float, help="printed total area (m2) to compare with the footprint")
ap.add_argument("--style", choices=["auto", "solid", "hollow"], default="auto",
                help="solid = filled black walls; hollow = walls drawn as two thin lines")
ap.add_argument("--wall-min", type=float, default=0.08, help="thinnest real wall (m)")
ap.add_argument("--wall-max", type=float, default=0.35, help="thickest real wall (m); closing size for hollow style")
ap.add_argument("--min-len", type=float, default=0.25, help="shortest wall piece kept (m); piers and corner stubs need this small")
ap.add_argument("--min-gap", type=float, default=0.40, help="narrowest opening (m)")
ap.add_argument("--max-hole", type=float, default=1.30,
                help="widest gap turned into a wall hole (m). Wider gaps stay open and are listed under 'gaps'")
ap.add_argument("--height", type=float, default=2.7)
ap.add_argument("--grid", action="store_true", help="write grid.png (100 px grid with labels) to read pixel positions")
ap.add_argument("--out", default="plan.json")
a = ap.parse_args()

g = cv2.imread(a.image, cv2.IMREAD_GRAYSCALE)
if g is None: sys.exit("cannot read image")
H, W = g.shape

if a.grid or (a.ppm is None and not a.dim):
    gi = cv2.cvtColor(g, cv2.COLOR_GRAY2BGR)
    for v in range(0, W, 100):
        cv2.line(gi, (v, 0), (v, H), (255, 160, 0), 1); cv2.putText(gi, str(v), (v + 2, 12), 0, 0.4, (200, 0, 0), 1)
    for v in range(0, H, 100):
        cv2.line(gi, (0, v), (W, v), (255, 160, 0), 1); cv2.putText(gi, str(v), (2, v - 2), 0, 0.4, (200, 0, 0), 1)
    cv2.imwrite("grid.png", gi); print("wrote grid.png (pixel coordinates, 100 px spacing)")
    if a.ppm is None and not a.dim: sys.exit("give --ppm or --dim to continue")

def seg(spec):
    x1, y1, x2, y2, m = [float(t) for t in spec.split(",")]
    return math.hypot(x2 - x1, y2 - y1), m
ppm = a.ppm if a.ppm else (lambda d: d[0] / d[1])(seg(a.dim))
warnings = []

_, ink = cv2.threshold(g, 0, 255, cv2.THRESH_BINARY_INV | cv2.THRESH_OTSU)
# drop small blobs (letters, ticks, symbols) BEFORE anything else
n, lab, st, _ = cv2.connectedComponentsWithStats(ink, connectivity=8)
small = np.isin(lab, [i for i in range(1, n) if max(st[i][2], st[i][3]) < 0.3 * ppm])
ink[small] = 0
k = max(2, int(round(a.wall_min * ppm)))
L = max(3, int(round(a.min_len * ppm)))

def find_bars(style):
    m0 = ink
    if style == "hollow":
        kc = int(round(a.wall_max * ppm)) | 1
        m0 = cv2.morphologyEx(ink, cv2.MORPH_CLOSE, np.ones((kc, kc), np.uint8))
    solid = cv2.morphologyEx(m0, cv2.MORPH_OPEN, np.ones((k, k), np.uint8))
    bars = []
    for o, ker in (("h", (L, 1)), ("v", (1, L))):
        m = cv2.morphologyEx(solid, cv2.MORPH_OPEN, np.ones((ker[1], ker[0]), np.uint8))
        cnt, _, s, _ = cv2.connectedComponentsWithStats(m, connectivity=8)
        for x, y, w, h, _ar in s[1:]:
            if o == "h" and w >= h * 1.2: bars.append((o, y + h / 2, x, x + w, h))
            if o == "v" and h >= w * 1.2: bars.append((o, x + w / 2, y, y + h, w))
    return bars

style = a.style
bars = find_bars("solid" if style in ("auto", "solid") else "hollow")
if style == "auto" and len(bars) == 0:
    style = "hollow"; bars = find_bars("hollow")
    print("auto: no solid walls found, retried as hollow (double-line) walls")
if not bars: sys.exit("0 walls found: check --ppm, --style, --wall-min (a wrong ppm is the usual cause)")

# ---- group collinear bars, merge across door/window gaps -------------------
tol = max(2.0, 0.6 * k)
walls, gaps = [], []          # gaps: wide gaps left open (px rect: o,c,s,e,t)
for o in ("h", "v"):
    bs = sorted([b for b in bars if b[0] == o], key=lambda b: b[1])
    groups = []
    for b in bs:
        if groups and b[1] - groups[-1][-1][1] <= tol: groups[-1].append(b)
        else: groups.append([b])
    for grp in groups:
        grp.sort(key=lambda b: b[2])
        cur = None
        for _, c, s, e, t in grp:
            if cur is None:
                cur = dict(o=o, c=c, s=s, e=e, t=t, gaps=[], cs=[c]); continue
            gap = s - cur["e"]
            if gap <= a.min_gap * ppm and gap < 0.3 * ppm:   # drawing glitch or touching pieces: join
                if gap > 2: warnings.append(f"joined a {gap/ppm:.2f} m crack in a {o} wall near px {int(s)}")
                cur["e"] = max(cur["e"], e)
            elif gap < a.min_gap * ppm:
                cur["e"] = max(cur["e"], e); warnings.append(f"gap of {gap/ppm:.2f} m (<min-gap) joined near px {int(s)}")
            elif gap <= a.max_hole * ppm:
                cur["gaps"].append((cur["e"], s)); cur["e"] = e
            else:
                walls.append(cur)
                gaps.append(dict(o=o, c=cur["c"], s=cur["e"], e=s, t=max(cur["t"], t)))
                cur = dict(o=o, c=c, s=s, e=e, t=t, gaps=[], cs=[c])
            cur["t"] = max(cur["t"], t); cur["cs"].append(c)
        walls.append(cur)
for w in walls: w["c"] = float(np.mean(w["cs"]))

def rect(o, c, s, e, t):
    return (int(s), int(c - t / 2), int(e), int(c + t / 2)) if o == "h" else (int(c - t / 2), int(s), int(c + t / 2), int(e))

wallmask = np.zeros((H, W), np.uint8)
for w in walls:
    x0, y0, x1, y1 = rect(w["o"], w["c"], w["s"], w["e"], w["t"]); cv2.rectangle(wallmask, (x0, y0), (x1, y1), 255, -1)
gapmask = np.zeros((H, W), np.uint8)
for q in gaps:
    x0, y0, x1, y1 = rect(q["o"], q["c"], q["s"], q["e"], q["t"]); cv2.rectangle(gapmask, (x0, y0), (x1, y1), 255, -1)

# ---- IR --------------------------------------------------------------------
M = lambda v: round(v / ppm, 3)
out = {"units": "m", "height": a.height, "source": a.image, "style": style,
       "scale": {"method": "dim" if a.dim else "ppm", "ppm": round(ppm, 3), "check_error_pct": None},
       "walls": [], "openings": [], "gaps": [], "floor": [], "rooms": [], "warnings": warnings}
for i, w in enumerate(walls):
    A, B = ([w["s"], w["c"]], [w["e"], w["c"]]) if w["o"] == "h" else ([w["c"], w["s"]], [w["c"], w["e"]])
    out["walls"].append({"id": f"w{i}", "a": [M(A[0]), M(A[1])], "b": [M(B[0]), M(B[1])], "t": M(w["t"]), "h": a.height})
    w["id"] = f"w{i}"
    if (w["e"] - w["s"]) < 0.3 * ppm: warnings.append(f"w{i} is shorter than 0.3 m")
    for j, (gs, ge) in enumerate(w["gaps"]):
        wid = (ge - gs) / ppm
        if wid > 0.85 * (w["e"] - w["s"]) / ppm: warnings.append(f"o{i}_{j} is wider than 85% of its wall")
        out["openings"].append({"id": f"o{i}_{j}", "wall": f"w{i}", "type": "door",  # a GUESS until semantics/hand edit
                                "offset": M((gs + ge) / 2 - w["s"]), "width": round(wid, 3),
                                "sill": 0.0, "height": 2.05, "confidence": "low"})
for q in gaps:
    c = [M(q["s"]), M(q["c"])] if q["o"] == "h" else [M(q["c"]), M(q["s"])]
    out["gaps"].append({"from": c, "o": q["o"], "width": M(q["e"] - q["s"]),
                        "hint": "left open (no wall). If it is a window in an outer wall, re-run with --max-hole above its width"})

# ---- footprint (floor slab) and rooms by flood fill ------------------------
seal = cv2.bitwise_or(wallmask, gapmask)          # wide gaps sealed only for the outside test
free = (seal == 0).astype(np.uint8)
n, lab = cv2.connectedComponents(free, connectivity=4)
border = set(np.unique(np.concatenate([lab[0], lab[-1], lab[:, 0], lab[:, -1]])).tolist()) - {0}
ext = np.isin(lab, list(border)) & (free == 1)
inside = ((~ext) & (free == 1)) | (seal > 0)
inside = (inside * 255).astype(np.uint8)
eps = 0.03 * ppm
cs, _ = cv2.findContours(inside, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
for c in cs:
    if cv2.contourArea(c) < 1.0 * ppm * ppm: continue
    ap_ = cv2.approxPolyDP(c, eps, True)[:, 0, :]
    out["floor"].append([[M(x), M(y)] for x, y in ap_])
foot_area = sum(cv2.contourArea(c) for c in cs if cv2.contourArea(c) >= ppm * ppm) / ppm / ppm
out["footprint_area_m2"] = round(foot_area, 2)
room_free = cv2.bitwise_and(inside, cv2.bitwise_not(wallmask))
nr, rl, rs, rc = cv2.connectedComponentsWithStats((room_free > 0).astype(np.uint8), connectivity=4)
ri = 0
for i in range(1, nr):
    if rs[i][4] < 1.0 * ppm * ppm: continue
    m = (rl == i).astype(np.uint8) * 255
    cc, _ = cv2.findContours(m, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
    big = max(cc, key=cv2.contourArea); p = cv2.approxPolyDP(big, eps, True)[:, 0, :]
    out["rooms"].append({"id": f"r{ri}", "name": None, "area_m2": round(rs[i][4] / ppm / ppm, 2),
                         "polygon": [[M(x), M(y)] for x, y in p], "floor": None,
                         "label_px": [int(rc[i][0]), int(rc[i][1])]}); ri += 1
if not out["rooms"]: warnings.append("no closed room found: the outline is not closed; check the overlay and gaps")

# ---- validation (reported, never fixed) -----------------------------------
def inrect(px, py, w):
    x0, y0, x1, y1 = rect(w["o"], w["c"], w["s"], w["e"], w["t"]); return x0 <= px <= x1 and y0 <= py <= y1
def near_gap(px, py):
    return any(abs(px - (q["s"] if q["o"] == "h" else q["c"])) < 3 + 0.2 * ppm and abs(py - (q["c"] if q["o"] == "h" else q["s"])) < 3 + 0.2 * ppm
               or abs(px - (q["e"] if q["o"] == "h" else q["c"])) < 3 + 0.2 * ppm and abs(py - (q["c"] if q["o"] == "h" else q["e"])) < 3 + 0.2 * ppm for q in gaps)
for w in walls:
    for end, sgn in ((w["s"], 1), (w["e"], -1)):
        p = end + sgn * w["t"] / 2
        px, py = (p, w["c"]) if w["o"] == "h" else (w["c"], p)
        if not any(v is not w and v["o"] != w["o"] and inrect(px, py, v) for v in walls) and not near_gap(px, py):
            warnings.append(f"{w['id']} has a free end near px ({int(px)},{int(py)}): missing wall or a real free end?")
errs = []
for spec in a.check:
    d, m = seg(spec); errs.append(abs(d / ppm - m) / m * 100)
if errs:
    out["scale"]["check_error_pct"] = round(max(errs), 2)
    if max(errs) > 2: warnings.append(f"scale check: worst printed-dimension error {max(errs):.1f}% (>2%): skew, non-uniform scan or misread dimension")
if a.area and abs(foot_area - a.area) / a.area > 0.05:
    warnings.append(f"footprint {foot_area:.1f} m2 differs from printed {a.area} m2 by more than 5% (footprint is measured to outer wall faces; printed areas are often interior)")
json.dump(out, open(a.out, "w"), indent=1)

# ---- overlay + crops --------------------------------------------------------
ov = cv2.cvtColor(g, cv2.COLOR_GRAY2BGR); tint = ov.copy()
rng = np.random.RandomState(3)
for r in out["rooms"]:
    cv2.fillPoly(tint, [np.array([[x * ppm, y * ppm] for x, y in r["polygon"]], np.int32)], tuple(int(v) for v in rng.randint(120, 255, 3)))
ov = cv2.addWeighted(ov, 0.6, tint, 0.4, 0)
for r in out["rooms"]: cv2.putText(ov, r["id"], tuple(r["label_px"]), 0, 0.7, (0, 120, 0), 2)
for w in walls:
    x0, y0, x1, y1 = rect(w["o"], w["c"], w["s"], w["e"], w["t"]); cv2.rectangle(ov, (x0, y0), (x1, y1), (0, 0, 255), 1)
byid = {w["id"]: w for w in walls}
os.makedirs("crops", exist_ok=True)
for o in out["openings"]:
    w = byid[o["wall"]]; c0 = w["s"] + o["offset"] * ppm - o["width"] * ppm / 2; c1 = c0 + o["width"] * ppm
    x0, y0, x1, y1 = rect(w["o"], w["c"], c0, c1, w["t"])
    cv2.rectangle(ov, (x0, y0), (x1, y1), (255, 0, 0), 2); cv2.putText(ov, o["id"], (x0, y0 - 4), 0, 0.45, (255, 0, 0), 1)
    cx, cy, R = (x0 + x1) // 2, (y0 + y1) // 2, int(1.5 * ppm)
    crop = cv2.cvtColor(g[max(0, cy - R):cy + R, max(0, cx - R):cx + R], cv2.COLOR_GRAY2BGR)
    cv2.imwrite(f"crops/{o['id']}.png", cv2.resize(crop, None, fx=max(1, 300 / max(1, crop.shape[1])), fy=max(1, 300 / max(1, crop.shape[0]))))
for q in gaps:
    x0, y0, x1, y1 = rect(q["o"], q["c"], q["s"], q["e"], q["t"]); cv2.rectangle(ov, (x0, y0), (x1, y1), (0, 140, 255), 2)
cv2.imwrite("overlay.png", ov)
print(f"style={style}  ppm={ppm:.1f}  {len(out['walls'])} walls, {len(out['openings'])} openings, {len(gaps)} wide gaps left open, "
      f"{len(out['rooms'])} rooms, footprint {foot_area:.1f} m2 -> {a.out}, overlay.png, crops/")
for wmsg in warnings: print("WARNING:", wmsg)
```

### Known limits of this MVP code

- Opening type is a guess until the semantics step or a manual edit; `door` is the default.
- Axis-aligned walls only; pieces under 0.25 m are dropped.
- Gaps wider than `--max-hole` are never holes (see step 2).
- Measured gap widths are about 1 to 3 cm narrower on double-line plans, and anti-aliased edges add a similar error on solid plans; this is within what a 1:100 raster can resolve (1 px = 1 cm at 100 ppm), but at 30 ppm one pixel is 3 cm, so scan at 200 dpi or more.
- Windows are plain holes (no glass), doors have no leaves, there is no ceiling.
- The GLB exports without the hemisphere light (the exporter warns); geometry and materials export. Room polygons sit 3 mm above the slab, which can show z-fighting at grazing angles in some viewers.
- The `check` and `area` options validate the drawing and the footprint; they cannot find a wall the extractor never saw (the overlay is for that).

## 10. Roadmap after the MVP

1. **Real-plan hardening (first):** run on 3 to 5 of your own plans, record every miss in the overlay, and tune the flags; add vector-PDF extraction if your plans are CAD exports.
2. **Rooms and finishes:** per-room material table from names, door leaves, window glass, ceilings, cutaway toggle.
3. **Blender backend:** `pip install bpy` (test first), a script that reads `plan.json`, builds walls with `bmesh`, cuts openings with Boolean difference of box cutters, adds frames, sun and area lights, Cycles stills, `.blend`/`.glb`. Alternatively drive a running Blender through its MCP add-on if you have Blender on your own machine.
4. **Editor:** a canvas page to drag wall ends and toggle opening types, writing back to `plan.json`.
5. **Hard inputs:** diagonal walls, hand sketches, photos with homography, multi-storey, optional IFC export.

## 11. Acceptance test (how you know it works)

Use one real plan with at least three printed dimensions. Each check maps to a file the MVP produces:
(a) `plan.json` `scale.check_error_pct` is at most 2 (from `--check` on every printed dimension other than the one used for `--dim`).
(b) Doors and windows: the counts in `semantics.json` equal what you count by eye on the plan, and `apply_semantics.py` prints `applied`.
(c) `overlay.png`: every wall in the source image has a red outline, no red outline sits on empty paper, and `warnings` in `plan.json` is empty or each entry is explained.
(d) `render_top.png` has the same orientation as the original plan (compare a distinctive corner; not mirrored) and the same outline (an L stays an L).
(e) Size: open `model.glb` in Blender, select the wall for `w0`, and compare its length with the length from `plan.json` (`|b - a|` plus the thickness `t` at the ends where the bar includes a corner); they should match to the centimetre.
Pass only if all five hold.
