# Turning a 2D floor plan into a 3D model: build plan

## Bottom line

Build a pipeline in which **geometry is extracted once into a small, human-checkable JSON file (the "plan IR"), and everything downstream (3D model, renders, viewer) is generated deterministically from that file.** Use computer vision for walls, OCR for dimensions and room labels, and a vision-language model (VLM) to classify and cross-check. Use AI image generators only for decorative renders, never as the source of geometry.

Reason: walls extracted from a raster plan are never perfect, and wrong geometry cannot be repaired once baked into a render or image. A pipeline with a verification overlay the user can see and a JSON they can edit beats a one-shot converter. This is a design judgement, not a measured result. All numbers below labelled "tested" come from runs on synthetic plans in this container; any figure labelled "expect" is an unmeasured estimate.

| Layer | Tool | Why |
|---|---|---|
| PDF/scan intake | PyMuPDF (`fitz`) rasterise at known dpi | Gives a pixel scale you can compute exactly |
| Wall extraction | OpenCV (threshold, morphology, contours) | Deterministic, debuggable, no GPU |
| Dimensions and labels | Tesseract (`pytesseract`) and/or a VLM | OCR for numbers; VLM to tell room names from dimensions |
| Geometry | Shapely | Wall unions, floor footprint, later door cuts |
| 3D mesh | trimesh (+ scipy, mapbox_earcut) to GLB | Pure Python, watertight extrusions |
| Viewer | three.js or `<model-viewer>` in a static page | Interactive, shareable, screenshot via Playwright |
| Photoreal renders | Blender headless or via MCP | Materials, lights, Cycles, video |
| Optional images | AI image generator on a clay render | Mood boards only |

## Assumptions

1. Input: single-storey plan as PNG/JPG/scan or PDF, mostly orthogonal walls, drawn conventionally (thick dark wall strokes, thinner dimension lines and text).
2. At least one real-world length is known (a printed dimension, a scale note with known page size, or a user-measured wall). With none, the model has no true scale; say so rather than guess. Door-width fallback (0.8 to 0.9 m) is a rough check only.
3. Ceiling height defaults to 2.7 m; wall thickness is measured from the drawing.
4. Deliverable is a viewable model and renders, not IFC/BIM (later extension).
5. Container: Linux, Python 3.13, Node, Chromium, Playwright, pip working. Blender and Tesseract were not found, so v0.1 avoids them.
6. Curved walls, multiple storeys, sloped roofs, hand sketches: out of the first version.
7. Coordinate convention: build Z-up in the IR, **export Y-up** (glTF, three.js and Blender's glTF importer all expect Y-up).

## Architecture

```
plan.pdf/png/jpg
   |
[1 Intake]  rasterise PDF at known dpi, deskew, crop title block
   |
[2 Scale]   px_per_m  <- user two-point measure | OCR dimension | scale note + dpi | door fallback
   |
[3 Extract] walls (thick strokes) | floor footprint | openings | rooms | text
   |
[4 Plan IR] plan.json (metres): walls[], openings[], rooms[], scale{source}, needs_review[]
   |        ^
   |        +-- overlay.png (IR over the original) -> human/VLM review -> fix -> re-run
   |
[5 Build]   extrude walls, floor slab, openings -> house.glb (Y-up)
   |
[6 Present] three.js viewer + Playwright screenshots; Blender renders + video
```

v0.1 (below) implements stages 1 to 3 and 5 in one script, skips the JSON IR, and writes `overlay.png` for verification. The IR arrives in extension step 3.

### Plan IR (suggested schema, for step 3 onward)

```json
{
  "units": "m", "height": 2.7,
  "scale": {"px_per_m": 50.0, "source": "user|ocr_dimension|scale_note_dpi|door_default"},
  "walls": [{"id": "w1", "a": [0,0], "b": [8,0], "thickness": 0.2, "kind": "exterior|interior"}],
  "openings": [
    {"id": "d1", "type": "door",   "wall": "w5", "t": 0.40, "width": 0.9, "sill": 0.0, "head": 2.1},
    {"id": "n1", "type": "window", "wall": "w2", "t": 0.50, "width": 1.2, "sill": 0.9, "head": 2.1}
  ],
  "rooms": [{"id": "r1", "label": "Kitchen", "polygon": [[0,0],[4,0],[4,3],[0,3]], "floor": "tile"}],
  "needs_review": ["w7 length ambiguous", "n3 might be a door"]
}
```

Centre-line walls with thickness are chosen because corners can be snapped, small gaps closed, and openings cut by position `t` along a wall, all awkward on pixel-derived outlines.

## Pipeline detail

### 1. Intake

- **Default for PDFs: rasterise and run the same raster path.** With PyMuPDF, `page.get_pixmap(dpi=200)`. Because you chose the dpi, you know the pixel size of the page exactly, which feeds the scale step.
- **Optional direct vector path (later, not v0.1).** `page.get_drawings()` returns every stroke (walls, dimension lines, furniture, hatching, door arcs, text outlines) with no semantics, and double-line walls arrive as pairs of parallel lines. To use it you must: filter by stroke width and colour/layer, pair parallel segments whose spacing is a plausible wall thickness to get centre-lines, take the page transform matrix and any form-XObject scaling into account, and still classify openings. Its benefit is sub-pixel exactness and no scan noise; its cost is that classification work. Try it only if rasterised CV fails on a vector PDF.
- Scans: rasterise at 200-300 dpi, deskew from the dominant Hough angle, crop title blocks and borders (a thick border becomes a "wall").

### 2. Scale (the biggest accuracy lever)

The user has an image, not a pixel scale. Ways to get `px_per_m`, in priority order:

1. **Two-point measure (works for v0.1, no OCR).** Open the image in any viewer that shows pixel coordinates, read the pixel positions of both ends of a wall that has a printed dimension, and compute `px_per_m = pixel_distance / metres`. Example: a wall printed as 8.00 m spans x = 50 to 450, so 400 px / 8 m = 50 px/m. Measure along a long dimension: a 2 px click error on 400 px is 0.5%, but on a 40 px door it is 5%. Use the outer dimension, then check a second one.
2. **OCR of dimension strings** (`4200`, `4.20 m`, `13'-6"`) paired with extension-line pixel endpoints. Parse feet-inches carefully and infer mm vs m by plausibility.
3. **Scale note plus known page size.** `px_per_m = dpi / 25.4 * 1000 / N` for a "1:N" drawing rasterised at `dpi` from a PDF at its original print size. Example: 1:100 at 200 dpi gives 78.74 px/m (computed). Invalid if the PDF was resized or the image is a screenshot.
4. **Door-width fallback**, low confidence.

Cross-check: with 3 or more dimensions, compute `px_per_m` for each; a spread above about 3% sets `needs_review` (drawing may not be to scale). Dimension chains should sum to the overall dimension within rounding. The 3% figure is a judgement call, not derived.

### 3. Walls

- **A. Thick-stroke mask (v0.1).** Otsu threshold, then a morphological opening with a square kernel just under the minimum wall thickness; thinner strokes (text, dimension lines, furniture, hatching) vanish. Kernel size is `min_wall_m * px_per_m`, so it **depends on the scale**: at low resolution the kernel clamps to 3 px and thin walls disappear. v0.1 prints a warning when the kernel is under 4 px.
- **B. Centre-line extraction.** Skeletonise, trace the graph, simplify (Douglas-Peucker), snap near-orthogonal angles to 0/90 when within about 3 degrees, merge collinear segments, close gaps shorter than a wall thickness, thickness from the distance transform. Produces the IR walls.
- **C. Hatched or double-line walls.** Fill closed thin-line regions by flood fill or close the gap between parallel lines with dilation, then continue as A. Expect this to be the most common failure of A on professional drawings; the share of plans that need it is unmeasured.
- **D. Learned segmentation** (CubiCasa5k-style) for noisy scans. Needs GPU or slow CPU inference and a licence check; its output still needs B. Use only if A to C fail. Hand sketches and photographed paper will likely need D or VLM-assisted tracing.

### 4. Floor footprint (gaps in the outer wall)

The floor cannot be derived from the wall polygon's own outline: a front door drawn as a gap makes the wall union a C shape with no interior, and the "exterior ring" is then just the wall footprint. v0.1 instead closes gaps up to `--max-door-m` (default 1.3 m) with a morphological closing, takes the external contour of the result and fills it. This was tested with a 1.2 m outer gap. Limits: a gap wider than `--max-door-m` (large sliding doors, open verandas) leaves the footprint open and the floor missing, and the closing also bridges narrow courtyards or light wells of the same width. Raise the parameter or add a footprint hint in those cases.

### 5. Openings: doors and windows

Detection cues, strongest first: gaps in the wall mask, door swing arcs (Hough circles or contour curvature; give hinge and swing side), window glyphs (parallel thin lines within the wall thickness), OCR tags (`D1`, `W2`), and a VLM pass on a crop around each candidate ("door, window or neither; which side?"). Use the VLM for the type and CV for position and width, since VLMs are weak at measuring (an assumption to verify on your plans; no accuracy figure is claimed).

**v0.1 does not model openings correctly.** A gap in the mask becomes a slot through the whole wall height: no lintel above a door (it should stop at about 2.1 m), and a window drawn as a gap becomes a floor-to-ceiling slot; windows drawn as thin lines inside a wall stay solid. Proper handling is extension step 4: cut by `sill`/`head` from the IR (door 0.0 to 2.1 m, window 0.9 to 2.1 m by default) and add frame and glass meshes.

### 6. Rooms, materials, lighting

Rooms are the enclosed free regions: Shapely `polygonize` on wall boundaries, or flood fill after bridging door gaps with a temporary bar. Labels by point-in-polygon of OCR text. Material table keyed on label (tile for kitchen/bath, wood for living/bedroom). In GLB use PBR base colour and roughness.

Viewer: `HemisphereLight` plus one shadow-casting `DirectionalLight`, `PCFSoftShadowMap`, ACES tone mapping, sRGB output, `OrbitControls`, clipping plane or ceiling toggle. Photoreal: Blender Sun plus Sky, area lights at windows, Cycles with denoising; CPU Cycles at modest samples is slow (expect minutes per frame; unmeasured here) and EEVEE needs GPU or software GL. Install Blender and test a trivial scene first; do not assume it renders in the container.

### 7. Outputs

| File | What it is |
|---|---|
| `plan.json` | The IR, source of truth, editable (step 3 onward) |
| `overlay.png` | Walls in red and floor footprint in blue over the original (written by v0.1) |
| `house.glb` | Y-up 3D model |
| `index.html` | three.js viewer (extension 1) |
| `top.png`, `iso.png`, `eye_*.png` | Top-down, isometric cutaway, eye-level renders |
| `walkthrough.mp4` | Optional camera path |
| `report.md` | Scale source, `needs_review` items, measured vs drawn dimensions |

## Minimal first version (v0.1, built and tested)

A plan image in, a Y-up GLB with walls and a floor slab plus `overlay.png` out, scale from one number, with sanity warnings. No OCR, Blender or explicit openings.

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install opencv-python-headless numpy shapely trimesh mapbox_earcut scipy
```

`scipy` is required: GLB export of a coloured mesh failed in testing without it.

`plan2glb.py`:

```python
#!/usr/bin/env python3
"""v0.1: plan image -> Y-up GLB + overlay.png, with sanity checks.
Usage: plan2glb.py plan.png --px-per-m 50 [--height 2.7] [--min-wall-m 0.08] [--max-door-m 1.3] [-o house.glb]"""
import argparse, sys, cv2, numpy as np, trimesh
from shapely.geometry import Polygon
from shapely.ops import unary_union

def polys_from_mask(mask, px_per_m, H, min_area=0.05):
    cnts, hier = cv2.findContours(mask, cv2.RETR_CCOMP, cv2.CHAIN_APPROX_SIMPLE)
    if hier is None: return None
    hier = hier[0]
    def to_m(c):
        c = cv2.approxPolyDP(c, 1.5, True)[:, 0, :].astype(float)
        if len(c) < 3: return []
        return [(x / px_per_m, (H - y) / px_per_m) for x, y in c]
    out = []
    for i, c in enumerate(cnts):
        if hier[i][3] != -1 or len(c) < 3: continue
        shell = to_m(c)
        if len(shell) < 4: continue
        holes = [h for h in (to_m(cnts[j]) for j in range(len(cnts)) if hier[j][3] == i) if len(h) >= 4]
        p = Polygon(shell, holes).buffer(0)
        if p.area > min_area: out.append(p)
    return unary_union(out) if out else None

def main():
    ap = argparse.ArgumentParser(); ap.add_argument("plan"); ap.add_argument("--px-per-m", type=float, required=True)
    ap.add_argument("--height", type=float, default=2.7); ap.add_argument("--min-wall-m", type=float, default=0.08)
    ap.add_argument("--max-door-m", type=float, default=1.3); ap.add_argument("-o", default="house.glb")
    a = ap.parse_args(); ppm = a.px_per_m; warns = []
    img = cv2.imread(a.plan, cv2.IMREAD_GRAYSCALE)
    if img is None: sys.exit(f"cannot read {a.plan}")
    H, W = img.shape
    _, bw = cv2.threshold(img, 0, 255, cv2.THRESH_BINARY_INV + cv2.THRESH_OTSU)
    k_raw = a.min_wall_m * ppm
    if k_raw < 4: warns.append(f"resolution low: {ppm:.0f} px/m gives a {k_raw:.1f}px kernel; walls thinner than ~{3/ppm:.2f} m will be erased. Re-rasterise at higher dpi.")
    k = max(3, int(round(k_raw)))
    walls = cv2.morphologyEx(bw, cv2.MORPH_OPEN, cv2.getStructuringElement(cv2.MORPH_RECT, (k, k)))
    frac = (walls > 0).mean()
    if frac > 0.35: warns.append(f"{frac:.0%} of the image is 'wall': floor fills/hatching/dark scan probably merged into walls")
    if frac < 0.005: warns.append("almost no wall pixels found: wrong threshold, light lines, or --px-per-m too small")
    wp = polys_from_mask(walls, ppm, H)
    if wp is None: sys.exit("no walls found")
    # Floor footprint: close gaps up to max door width (so an open front door doesn't open the outline),
    # then fill everything inside the outer contour. Pixel-space closing keeps square corners.
    kc = int(round(a.max_door_m * ppm)) | 1
    closed = cv2.morphologyEx(walls, cv2.MORPH_CLOSE, cv2.getStructuringElement(cv2.MORPH_RECT, (kc, kc)),
                              borderType=cv2.BORDER_CONSTANT, borderValue=0)
    ext, _ = cv2.findContours(closed, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
    filled = np.zeros_like(closed); cv2.drawContours(filled, ext, -1, 255, -1)
    fp = polys_from_mask(filled, ppm, H)
    geoms = list(wp.geoms) if hasattr(wp, "geoms") else [wp]
    meshes = []
    for g in geoms:
        m = trimesh.creation.extrude_polygon(g, a.height); m.visual.face_colors = [225, 225, 220, 255]; meshes.append(m)
    slab = 0.15
    for e in (list(fp.geoms) if hasattr(fp, "geoms") else [fp]):
        f = trimesh.creation.extrude_polygon(Polygon(e.exterior), slab); f.apply_translation([0, 0, -slab])
        f.visual.face_colors = [150, 130, 110, 255]; meshes.append(f)
    sc = trimesh.Scene(meshes)
    # glTF is Y-up; we built Z-up. Rotate -90 deg about X: (x,y,z) -> (x,z,-y)
    sc.apply_transform(trimesh.transformations.rotation_matrix(-np.pi / 2, [1, 0, 0]))
    sc.export(a.o)
    x0, y0, x1, y1 = wp.bounds; w, d = x1 - x0, y1 - y0
    if not (3 <= max(w, d) <= 60): warns.append(f"footprint {w:.1f} x {d:.1f} m is implausible for a house: check --px-per-m")
    ov = cv2.cvtColor(img, cv2.COLOR_GRAY2BGR); ov[walls > 0] = (0, 0, 255)
    ov[(filled > 0) & (walls == 0)] = (0.6 * ov[(filled > 0) & (walls == 0)] + 0.4 * np.array([255, 200, 0])).astype(np.uint8)
    cv2.imwrite("overlay.png", ov)
    print(f"walls {wp.area:.2f} m2, floor {fp.area:.2f} m2, bounds {w:.2f} x {d:.2f} m, wall-pixel fraction {frac:.1%}, wrote {a.o} + overlay.png")
    for s in warns: print("WARNING:", s)
main()
```

Run: `python plan2glb.py plan.png --px-per-m 50 -o house.glb`

### What was tested (Python 3.13, OpenCV 5.1, Shapely 2.2, trimesh 5.2, this container)

Test plan `mk.py`: 8 x 6 m footprint, 0.2 m walls (10 px at 50 px/m), a partition with a 1.2 m interior door gap, a 1.2 m **front-door gap in the outer wall**, a text label and a thin dimension line.

```python
import cv2, numpy as np
img=np.full((400,500,3),255,np.uint8)
cv2.rectangle(img,(50,50),(450,350),(0,0,0),10)
cv2.line(img,(250,50),(250,350),(0,0,0),10)
cv2.rectangle(img,(240,150),(260,210),(255,255,255),-1)      # interior door gap
cv2.rectangle(img,(100,345),(160,355),(255,255,255),-1)      # front door gap in outer wall
cv2.putText(img,"Living 4.0 x 6.0",(70,120),cv2.FONT_HERSHEY_SIMPLEX,0.6,(0,0,0),1)
cv2.line(img,(50,30),(450,30),(0,0,0),1)
cv2.imwrite("plan.png",img)
```

Results:
- Output: `walls 6.29 m2, floor 50.55 m2, bounds 8.20 x 6.20 m`. Hand check: wall ring 5.60 + partition 1.16 minus both 0.24 gaps = 6.28 m2 (match within 0.2%); floor 8.2 x 6.2 = 50.84 m2 (0.6% low, from contour simplification). The floor exists despite the open front door.
- Reloading `house.glb` with trimesh gives y range -0.15 to 2.70, so height is on Y (glTF convention). Both meshes watertight.
- Text and the dimension line were removed by the opening.
- Downscaling the plan 0.4x (about 20 px/m): wall area fell to 4.62 m2 because the 0.2 m partition was eroded, and the script printed the low-resolution warning. Wrong scale (5 px/m): printed an implausible-footprint warning (82 x 62 m).
- A uniform dark image: "no walls found". A crash on degenerate contours at 5 px/m was found and fixed.

Not tested: real scans, PDF input, Otsu on coloured or hatched fills (the "fill-everything" warning is untested on a real example), loading the GLB into three.js or Blender, Chromium rendering. The Y-up claim rests on the glTF specification and the reloaded bounds, not on a viewer.

### Acceptance test per real plan

What v0.1 can do now:
1. Open `overlay.png`: red walls should coincide with the drawn walls; blue should cover rooms but not the exterior. No missing or phantom walls.
2. Check printed wall-pixel fraction and footprint for plausibility, and that no WARNING appeared.
3. Check three printed dimensions against the GLB bounds or ray casts, each within about 2% (a working tolerance, not a standard).
4. Mesh watertight, no zero-area faces.
5. Load in three.js (once the viewer exists): the model stands upright with the roof direction up.

Needs later steps: room polygons closed and room areas within about 3% of printed areas (needs rooms, extension 5); wall classification and door counts (extension 3 to 4).

## Extension path (each step keeps the previous one working)

1. **Viewer.** `index.html` with `GLTFLoader` and `OrbitControls`, Playwright screenshots to `top.png` and `iso.png`. Chromium has no GPU here: try `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`. Untested; if WebGL context creation fails, those flags are the first thing to adjust. This step also confirms upright orientation.
2. **Scale from OCR.** `apt-get install tesseract-ocr`, dimension parsing, fall back to the CLI flag when the spread check fails.
3. **Centre-line IR.** Skeleton, snap, merge, `plan.json`; rebuild from the IR; room polygons.
4. **Explicit openings.** Detection plus VLM classification; cut with sill and head; frames and glass; lintels over doors.
5. **Rooms and materials.** `polygonize`, labels, per-room floors, room-area check.
6. **Blender renders.** `blender -b -P render.py -- house.glb` (the importer treats glTF as Y-up, matching our export), sun/area lights, Cycles denoised, top/iso/eye PNGs. Use Blender MCP for interactive tweaking, headless script as the reproducible path.
7. **Video and pretty images.** Camera path to MP4; optional AI image variants of a clay render, labelled as illustrations.
8. **IFC/DXF export** only if needed.

## Risks and failure cases

| Risk | Symptom | Mitigation |
|---|---|---|
| Wrong scale | Model looks right, all dimensions off by one factor | Scale has a source; cross-check several dimensions; plausibility warning on footprint |
| Low resolution | Thin walls silently erased | Kernel warning; rasterise at higher dpi |
| Open outer gap wider than `--max-door-m` | No floor, open footprint | Raise parameter; inspect `overlay.png` blue region |
| Hatched or double-line walls | Walls vanish or fragment | Approach C; lower kernel; vector input |
| Coloured floor fills or dark scans | Whole image becomes one "wall" | Wall-fraction warning; convert fills to white; use a fixed threshold |
| Text, furniture, stairs mistaken for walls | Phantom blobs | Opening kernel; area/aspect filters; review overlay |
| Door arcs and glyphs merge with walls | Missing or filled doorways | Detect arcs first and subtract; VLM crop check |
| Gaps in wall outline (scan breaks) | Floor leaks, wrong footprint | Closing step; check overlay |
| Openings full height in v0.1 | No lintels, windows are floor-to-ceiling slots | Extension step 4 |
| Z-up export | Model on its side in viewers | Rotate to Y-up at export (done); check upright in viewer |
| Non-orthogonal or curved walls | Snapping distorts | Make snapping optional |
| Drawing not to scale | Dimensions contradict | Spread check; trust printed numbers |
| Several plans or floors on one sheet | Buildings merged | Segment by connected components |
| Imperial units | `13'-6"` mis-parsed | Parser unit tests |
| AI generator used for geometry | Hallucinated rooms | Never; decoration only |
| No GPU | Slow or failing renders | CPU Cycles, low samples, or render locally |
| Blender/Tesseract absent | Steps 2 and 6 blocked | Install; v0.1 avoids them |
| Privacy of home plans | Leaks via external APIs | Keep CV local; send crops only to an approved VLM |

## Decision summary

- Extract geometry once, verify it visually, build from it; AI image generators only decorate.
- Start with v0.1: thick-stroke morphology, one measured scale number, footprint fill, Y-up export, overlay and warnings. Verified on synthetic plans only; treat the first real plan as the next experiment.
- Next in order: viewer (confirms orientation), OCR scale, centre-line IR, explicit openings, Blender renders.
