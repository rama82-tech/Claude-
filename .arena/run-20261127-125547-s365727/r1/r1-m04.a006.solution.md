# Turning a 2D floor plan into a 3D model: build plan

## Recommendation in one paragraph

Do not go straight from pixels to 3D. Go **plan image -> a small, human-checkable JSON description (walls, openings, rooms, scale) -> deterministic geometry code -> GLB file -> renders**. Claude's vision reads the plan into the JSON, a short script draws the JSON back over your image so you can see mistakes in seconds, and plain Python turns the JSON into a model. The JSON is the product: it is the one place where accuracy is decided, and it is cheap to correct by hand. AI image generators are an optional last step for pretty pictures, never the source of geometry.

## Assumptions

- Input is one floor of a residential plan as PNG/JPG/PDF with at least one printed dimension (e.g. `30'-0"`) or a scale bar. Mostly straight, orthogonal walls. Curved walls, stairs and multi-storey buildings are out of scope for v1.
- You are in the Claude Code cloud container: Python 3, Node, Chromium/Chrome present. I assumed Blender is **not** installed and no GPU is available.
- "3D model" means a file you can orbit in a browser, open in Blender and render stills from. Not a construction-grade BIM model.
- Defaults when the plan gives none: wall 2.7 m, exterior wall 8" (0.2032 m), interior 4.5" (0.1143 m), door head 2.1 m, window sill 0.9 m and head 2.1 m. They live in the JSON and can be changed.

## What was actually run, and what was not

Everything below marked **tested** was run in this container: a fresh Python venv with exactly `pip install shapely trimesh numpy scipy mapbox-earcut pillow` (mapbox-earcut is required: without it `trimesh` raises "No available triangulation engine"), plus `npm i three@0.160.0 playwright-core` and the system Chrome (`CHROME=/usr/bin/google-chrome`) for the screenshots. Tested: `build.py`, `px2m.py`, `overlay.py`, `viewer.html`, `shot.mjs`; the GLB reloaded cleanly, and I looked at the top and isometric screenshots. **Not run**: vision extraction (it is an instruction to Claude, shown below), OCR, OpenCV snapping, and anything in Blender. The container's proxy blocks CDNs such as jsdelivr, which is why the viewer loads three.js from `node_modules`.

## Worked example (the numbers everything else is built on)

A 2-bedroom unit, 30'-0" x 24'-0", image 1200 x 960 px. The printed `30'-0"` dimension runs from x=100 to x=1100 px, and `24'-0"` from y=80 to y=880 px.

1. **Scale.** 1000 px = 30 ft gives 0.009144 m/px; 800 px = 24 ft gives the same. Free sanity checks: a 3'-0" door is about 100 px wide, a 6" wall about 17 px.
2. **Coordinates.** `x = (px - 100) * 0.009144`, `y = (880 - py) * 0.009144` (flip y). Stored in metres, wall **centrelines**, origin lower-left.
3. **Walls.** Four exterior walls (9.144 x 7.3152 m), one full-height interior wall at x = 18'-0" (5.4864 m), one short interior wall at y = 12'-0" running east from it.
4. **Openings** hang on a wall by `at` (distance along the wall to the opening centre), width, sill and head.
5. **Rooms** are found by polygonizing the wall centrelines; the JSON only gives a label point and a floor material.
6. **Result (tested):** 29 named meshes, all watertight, Y-up bounds x -0.10..9.25, y -0.2..2.7, z -7.42..0.10 m; clear floor Living 37.89 m2 (408 sq ft), Bed 1 and Bed 2 12.24 m2 (132 sq ft) each. Hand check: 18' x 24' = 432 sq ft centreline-to-centreline minus half the wall thicknesses.

## The files (all tested)

### `px_plan.json`: what the vision step produces (pixels, y down)

The vision model never does arithmetic: it reports pixel positions and the calibration pixels; code converts. (The example file lists only one door and one room to stay short; `plan.json` below has the full set.)

```json
{"calibration":{"x":[100,1100,9.144],"y":[80,880,7.3152]},
 "walls":[{"id":"W1","a":[100,880],"b":[1100,880],"kind":"exterior"},{"id":"W2","a":[1100,880],"b":[1100,80],"kind":"exterior"},
          {"id":"W3","a":[1100,80],"b":[100,80],"kind":"exterior"},{"id":"W4","a":[100,80],"b":[100,880],"kind":"exterior"},
          {"id":"W5","a":[700,880],"b":[700,80],"kind":"interior"},{"id":"W6","a":[700,480],"b":[1100,480],"kind":"interior"}],
 "openings":[{"id":"D1","wall":"W1","at_px":[400,880],"w_px":100,"type":"door"}],
 "rooms":[{"label":"Living","at_px":[300,500],"floor":"oak"}]}
```

Schema: `calibration.x = [px_start, px_end, metres]` for one printed horizontal dimension, `calibration.y` likewise for a vertical one. `walls`: id, `a`, `b` (pixel endpoints of the centreline), `kind` = `exterior` | `interior` | `divider` (divider: invisible, used only to split an open-plan room); thickness `t` optional. `openings`: wall id, `at_px` (pixel point at the opening centre, on the wall), `w_px`, `type`, optional `sill`/`head`. `rooms`: label point and floor material.

**Extraction prompt to give Claude with the image** (re-run on zoomed quadrant crops for dense plans): "Read this floor plan. Return only JSON in the px_plan.json schema. Use pixel coordinates of the image I attached, origin top-left. Walls as centrelines; two parallel lines or a black band is one wall. One entry per straight wall run; split where another wall T-joins. Do not invent walls under furniture, swing arcs or text. For each door or window give the pixel point at its centre on the wall and its width in pixels. For calibration pick the two longest printed dimension lines and give their end pixels and value in metres. Where unsure, add a field unsure: true instead of guessing."

### `px2m.py`: pixels to metres

```python
"""px_plan.json (pixels, y down) -> plan.json (metres, y up). Two printed dimensions give separate x and y scales."""
import json, sys
def convert(px, wall_h=2.7):
    c = px["calibration"]      # {"x":[px0,px1,metres], "y":[py0,py1,metres]}  (y: py0 = top end of the printed dimension)
    sx = c["x"][2]/abs(c["x"][1]-c["x"][0]); sy = c["y"][2]/abs(c["y"][1]-c["y"][0])
    skew = abs(sx-sy)/max(sx, sy)
    if skew > 0.02: print(f"WARNING: x/y scale differ by {skew:.1%}: using separate x and y scales; check the overlay")
    x0 = min(c["x"][:2]); y0 = max(c["y"][:2])           # origin: left end of x dimension, bottom end of y dimension
    f = lambda p: [round((p[0]-x0)*sx, 4), round((y0-p[1])*sy, 4)]
    walls = [{"id":w["id"], "a":f(w["a"]), "b":f(w["b"]), "t":w.get("t", .2032 if w["kind"]=="exterior" else .1143), "kind":w["kind"]} for w in px["walls"]]
    wl = {w["id"]: w for w in walls}
    ops = []
    for o in px["openings"]:           # px opening: wall, "at_px" = pixel point on the wall at the opening centre, "w_px"
        w = wl[o["wall"]]; a, b = w["a"], w["b"]; L = ((b[0]-a[0])**2+(b[1]-a[1])**2)**.5
        p = f(o["at_px"]); at = ((p[0]-a[0])*(b[0]-a[0])+(p[1]-a[1])*(b[1]-a[1]))/L   # project onto the wall
        wm = o["w_px"]*(sx if abs(b[0]-a[0]) >= abs(b[1]-a[1]) else sy)
        ops.append({"id":o["id"], "wall":o["wall"], "at":round(at,4), "w":round(wm,4), "type":o["type"],
                    "sill":o.get("sill", 0 if o["type"]=="door" else .9), "head":o.get("head", 2.1)})
    rooms = [{"label":r["label"], "at":f(r["at_px"]), "floor":r.get("floor","floor_default")} for r in px["rooms"]]
    return {"units":"m", "wall_height":wall_h, "walls":walls, "openings":ops, "rooms":rooms}
if __name__ == "__main__":
    json.dump(convert(json.load(open(sys.argv[1]))), open(sys.argv[2], "w"), indent=1)
```

### `build.py`: JSON to GLB

Run: `python build.py plan.json house.glb`.

```python
import json, sys, numpy as np, trimesh
from shapely.geometry import LineString, Point, Polygon, box
from shapely.ops import unary_union, polygonize
from shapely import affinity
from trimesh.visual.material import PBRMaterial

MAT = {  # role -> (baseColor RGBA 0-255, roughness, metallic)
  "wall_ext": ([225,222,214,255], .9, 0), "wall_int": ([240,238,232,255], .9, 0),
  "slab": ([120,120,120,255], .95, 0), "threshold": ([150,140,125,255], .8, 0),
  "oak": ([176,140,98,255], .6, 0), "carpet": ([150,150,160,255], 1, 0),
  "tile": ([200,205,210,255], .3, 0), "floor_default": ([190,190,190,255], .8, 0),
  "glass": ([170,210,230,90], .05, 0), "door": ([120,80,50,255], .6, 0)}

def pbr(role):
    c, r, m = MAT.get(role, MAT["floor_default"])
    return PBRMaterial(name=role, baseColorFactor=c, roughnessFactor=r, metallicFactor=m,
                       alphaMode="BLEND" if c[3] < 255 else "OPAQUE")

def polys(g):
    return [p for p in getattr(g, "geoms", [g]) if p.geom_type == "Polygon" and p.area > 1e-6]

def build(plan, out):
    H = plan["wall_height"]
    W = {w["id"]: w for w in plan["walls"]}
    solid = [w for w in plan["walls"] if w.get("kind") != "divider"]   # dividers: labelling only
    def rect(w):
        a, b = np.array(w["a"]), np.array(w["b"]); d = (b-a)/np.linalg.norm(b-a)
        return LineString([a-d*w["t"]/2, b+d*w["t"]/2]).buffer(w["t"]/2, cap_style="flat")
    ext = unary_union([rect(w) for w in solid if w["kind"] == "exterior"] or [Polygon()])
    intr = unary_union([rect(w) for w in solid if w["kind"] != "exterior"] or [Polygon()]).difference(ext)
    foot = unary_union([ext, intr])
    cut = {}
    for o in plan["openings"]:
        w = W[o["wall"]]; a, b = np.array(w["a"]), np.array(w["b"])
        d = (b-a)/np.linalg.norm(b-a); c = a + d*o["at"]
        r = box(-o["w"]/2, -w["t"]/2-0.01, o["w"]/2, w["t"]/2+0.01)
        r = affinity.rotate(r, np.degrees(np.arctan2(d[1], d[0])), origin=(0,0))
        cut[o["id"]] = affinity.translate(r, c[0], c[1])
    allcut = unary_union(list(cut.values()))
    scene = trimesh.Scene(); n = [0]
    def add(poly, z0, z1, role):
        for p in polys(poly):
            m = trimesh.creation.extrude_polygon(p, z1 - z0)
            m.apply_translation([0, 0, z0])
            m.visual = trimesh.visual.TextureVisuals(material=pbr(role))
            n[0] += 1; scene.add_geometry(m, node_name=f"{role}_{n[0]}", geom_name=f"{role}_{n[0]}")
    for role, f in (("wall_ext", ext), ("wall_int", intr)):
        add(f.difference(allcut), 0, H, role)
        for o in plan["openings"]:
            piece = f.intersection(cut[o["id"]])
            if o["sill"] > 0: add(piece, 0, o["sill"], role)
            add(piece, o["head"], H, role)
    # glass panes in windows (thin box in the middle of the wall)
    for o in plan["openings"]:
        if o["type"] == "window":
            piece = foot.intersection(cut[o["id"]])
            c = piece.centroid; ang = np.degrees(np.arctan2(*(np.array(W[o["wall"]]["b"])-np.array(W[o["wall"]]["a"]))[::-1]))
            g = affinity.rotate(box(-o["w"]/2, -0.01, o["w"]/2, 0.01), ang, origin=(0,0))
            add(affinity.translate(g, c.x, c.y), o["sill"], o["head"], "glass")
    lines = unary_union([LineString([w["a"], w["b"]]) for w in plan["walls"]])  # includes dividers
    rooms_union = []
    report = []
    for r in polygonize(lines):
        lab = next((q for q in plan["rooms"] if r.contains(Point(q["at"]))), None)
        fl = r.difference(foot)
        rooms_union.append(fl)
        report.append((lab["label"] if lab else "?", fl.area))
        print(f"room {lab['label'] if lab else '?'}: clear floor {fl.area:.2f} m2 = {fl.area*10.7639:.0f} sq ft")
        add(fl, -0.1, 0, lab["floor"] if lab else "floor_default")
    add(foot.intersection(allcut), -0.1, 0, "threshold")       # floor under every doorway/window
    # slab: fill each footprint polygon's exterior ring, so stray disconnected walls cannot crash this
    slab = unary_union([Polygon(p.exterior) for p in polys(foot)])
    add(slab, -0.2, -0.1, "slab")
    # glTF and three.js are Y-up: rotate the Z-up model -90 deg about X so plan-north becomes -Z, height becomes +Y
    scene.apply_transform(trimesh.transformations.rotation_matrix(-np.pi/2, [1, 0, 0]))
    scene.export(out)
    return scene

if __name__ == "__main__":
    plan = json.load(open(sys.argv[1])); sc = build(plan, sys.argv[2])
    ms = list(sc.geometry.values())
    print("meshes", len(ms), "watertight", all(m.is_watertight for m in ms))
    print("bounds (x, y=up, z)", sc.bounds.round(3).tolist())
    print("names", sorted(sc.geometry)[:6], "...")
```

Design choices, each fixing a failure I would otherwise hit: the work is done **in 2D with shapely** (union of wall rectangles, subtract opening rectangles, extrude), so T and L joints merge with no overlapping faces and no boolean library is needed. Floors are cut by the wall footprint, but a separate `threshold` piece is laid under every opening so there is no trench in doorways. The model is built Z-up and rotated -90 degrees about X on export, because glTF and three.js are Y-up (otherwise the house lies on its side). Every mesh is named by role and carries a PBR material, so Blender or three.js can swap materials by name. Blender's glTF importer converts Y-up back to Z-up itself. Stray disconnected walls no longer crash the slab; `divider` walls split rooms without producing geometry (both tested).

## Architecture

```
plan.png/pdf
   |
[1 Prepare]  render PDF page at 200-300 dpi, deskew, crop, find scale
   |
[2 Read]     Claude vision (prompt above) + OCR + OpenCV -> px_plan.json
   |
[3 Convert]  px2m.py -> plan.json (metres)
   |
[4 Verify]   overlay.py -> overlay.png; rule checks; you correct px_plan.json
   |
[5 Build]    build.py -> house.glb (+ .blend/.obj later)
   |
[6 View]     viewer.html + shot.mjs -> top.png, iso.png
   |
[7 Render]   (optional) Blender Cycles/EEVEE stills and walkthrough; (optional) AI polish
```

| Job | Use | Why |
|---|---|---|
| Reading the plan | Claude vision, with a crop-and-zoom loop for dense areas | Understands plan symbols (door swings, window glyphs, labels) that classical CV does not |
| Dimensions / text | `pytesseract` or `easyocr`; PyMuPDF for PDFs with a text layer | Vector PDFs often contain the dimension text exactly: extract it instead of OCRing it |
| Line geometry | OpenCV: threshold, `HoughLinesP`, morphological close | Snaps Claude's rough coordinates to real wall lines and measures thickness |
| Verification | Pillow overlay | Cheapest, highest-value step |
| Geometry | `shapely` + `trimesh` (v1); Blender `bpy` (v2) | Pure Python, pip-installable, no GPU |
| Viewing | three.js + Chrome via `playwright-core` | Works in the container |
| Photoreal renders | Blender headless (`blender -b -P render.py`), or a live Blender through its MCP add-on on your own machine | Real materials, sky, interior lights |
| Optional polish | AI image-to-image pass on a render | Looks good but invents details: label it as artwork |

## Step-by-step pipeline

1. **Normalise the input.** PDF with a text layer: extract text and vectors with PyMuPDF first; rasterise at 200-300 dpi for vision. Photo or scan: deskew, perspective-correct, crop.
2. **Calibrate scale.** Pick the mode by what the plan gives you:
   - **A. Uniform scale** (two printed dimensions on perpendicular axes agree within 2%): one scale for both axes.
   - **B. Separate x and y scales** (they disagree by more than 2%, typical of scans and stretched brochure images): `px2m.py` uses each axis's own scale and prints a warning; review the overlay and the door-width sanity check.
   - **C. Per-wall printed dimensions** (plan marked "not to scale", or a brochure plan whose drawing is distorted): treat printed room dimensions as constraints. Set each wall run's length from its printed number and use pixels only for topology and the openings' relative positions. This is manual in v1; say so in the report. The "within 1% of printed" acceptance test then applies to the printed numbers you fed in, not to the drawing.
   - **D. No dimension at all:** fall back to a standard 3'-0" door width (flagged low confidence), or ask. Refuse only when there is not even a door to measure. Never use "1/4" = 1'" from the title block unless the source DPI is known.
3. **Extract `px_plan.json`** with the prompt above. Convert in code (`px2m.py`), not in the model's head.
4. **Snap and clean (code, not AI).** Snap endpoints within about 1.5x wall thickness; snap near-horizontal/vertical segments to exact within 2 degrees; merge collinear segments; split where walls T-join; round to 1 inch; replace measured widths by standard values within tolerance (door 2'-6", 2'-8", 3'-0"; wall 4.5", 6", 8").
5. **Verify visually** with `overlay.py`, plus automatic checks: every room polygon closed; no wall shorter than its thickness; every opening leaves 0.1 m of solid wall at each end; every room has a door or opening; total area vs any printed area within 3%.
6. **Build** with `build.py`. Z-levels: slab -0.2 to -0.1, floor -0.1 to 0, walls 0 to 2.7 m. Ceilings are left out for cutaway views.
7. **Opening furniture (v2).** Windows already get a glass pane. Add door leaves (0.04 m box rotated about the hinge to 0 or 90 degrees, from the swing arc) and frames.
8. **Materials.** Roles are already in the mesh names and each has a PBR material (`wall_ext`, `wall_int`, `oak`, `carpet`, `glass`, `slab`, `threshold`). Add more floor types (`tile` for bath and kitchen) via the room's `floor` field. In Blender, swap by name for CC0 texture sets (Poly Haven, ambientCG).
9. **Lighting.** Browser: sun with shadows plus hemisphere light (in `viewer.html`). Blender: Nishita sky and sun at a chosen time and north angle (rarely on the plan: default it, expose one parameter), area lights in windows for interiors, Cycles 128-256 samples with denoising.
10. **Export and render.** `house.glb`; `house.blend`/`.obj`/`.fbx` for editing; stills `top.png`, `iso.png`, one eye-level view per main room; optionally a turntable from Blender.

## Getting the geometry accurate

- **Single source of truth.** All numbers live in the JSON; fixing a wall is fixing one line.
- **Centreline model.** Thickness is a property; corners and T joints come from the shapely union, so they are closed.
- **Prefer printed numbers to measured pixels.** If the plan prints "12'-0"" between two walls, use it. If printed chains do not add up to the overall dimension, report the difference instead of silently choosing.
- **Show the error.** `report.md`: per-room printed vs computed area, any opening that moved more than 3 inches in snapping, which scale mode was used.
- **Double-line walls.** Detect the pair, take the midline as centreline and the gap as thickness. Single-line plans only give default thickness.

## Trade-offs I chose (and what each costs you)

| Choice | I chose | Gives up |
|---|---|---|
| Vision + JSON review, vs a trained wall-segmentation model | Vision + review | Not fully automatic: you look at one overlay per plan. In return: no training data, any drawing style, every error visible and fixable. A CubiCasa5k-style model is faster per plan but fails on unfamiliar drawings and cannot read dimensions |
| Python shapely/trimesh first, Blender second | Python first | No photoreal render in v1. In return: `pip install` works here, tests run in seconds, and the JSON-to-geometry logic carries over to Blender |
| 2D footprint extrusion, vs boolean cuts in Blender | 2D extrusion | No arched openings, sloped ceilings or chamfered reveals without extra work. Robust, no boolean failures |
| Metric centrelines rounded to 1 inch | Yes | Old buildings off the inch grid are off by up to half an inch |
| Soft scale handling (modes A-D) over hard rejection | Yes | More judgement needed from you on bad scans; mode C is manual in v1. In return, brochure and not-to-scale plans still produce a model |
| AI image generation for renders | Optional last step | Inconsistent, invents rooms and furniture, not measurable |
| One storey, orthogonal walls | Yes | Stairs, curves, angled walls, several floors need v2 |

## Risks and failure cases

| Failure | What happens | Mitigation |
|---|---|---|
| No dimensions, only room names | Scale unknown, model could be 30% off | Mode D: door width (low confidence) or ask |
| Photo of a paper plan: perspective or curved page | Skew, varying scale | Four-point perspective correction; if still non-uniform use mode B or C |
| "Not to scale" or brochure plan | Pixel proportions wrong | Mode C: printed dimensions drive wall lengths |
| Dense or low-res scans, hatching, furniture, text over walls | Furniture lines taken as walls | Crop and zoom; ask for walls only; reject segments under 0.3 m not touching another wall |
| Swing arcs and window glyphs confused with walls or each other | Wrong openings | Openings must sit on a wall; arcs are never walls |
| Walls drawn as a solid black fill | Centreline hidden | `skimage.morphology.skeletonize` or distance-transform midline |
| Curved or diagonal walls | Orthogonal snapping flattens them | Turn snapping off per wall beyond 2 degrees; v1 accepts straight diagonals, not curves |
| Open plan: no wall between kitchen and living | Polygonize merges them | Add a `kind: "divider"` wall (no geometry, used for room splitting; tested) |
| Stray or detached wall segment | Used to crash the slab step | Fixed: slab fills each footprint polygon; also flagged by the checks in step 5 |
| Several floors or elevations on one sheet | Mixed scale | Detect and crop each drawing; ask which floor |
| Windows without sill/head | Defaults 0.9 / 2.1 m | Stated in the report |
| Vision hallucinates a coordinate | Wall in the wrong place | Overlay review is mandatory |
| Copyrighted or confidential plan | Sharing risk | Process locally; do not publish the plan image |
| Blender not installable in the container | No photoreal stills | Keep the three.js path as default; render in Blender on your own machine |
| No GPU for the browser view | Chrome falls back to software GL (`--use-gl=swiftshader`): slower but works (tested) | Keep the scene small |
| CDN blocked by the container proxy | CDN imports in `viewer.html` fail | Load three.js from `node_modules` (done) |

## Minimal first version

Goal: one image in, one orbitable GLB and two PNGs out, for a single-storey orthogonal plan with at least one printed dimension per axis.

1. `pip install shapely trimesh numpy scipy mapbox-earcut pillow` and `npm i three@0.160.0 playwright-core`.
2. Give Claude your plan image and the extraction prompt; save the answer as `px_plan.json`.
3. `python overlay.py plan.png px_plan.json overlay.png`; look, correct `px_plan.json`.
4. `python px2m.py px_plan.json plan.json` then `python build.py plan.json house.glb`.
5. `CHROME=/usr/bin/google-chrome node shot.mjs` for `top.png` and `iso.png`; serve the folder with any static server and open `viewer.html` to orbit.

Effort: the five scripts above already exist and ran, so the one to two days covers what is not written: running your real plans through the extraction prompt and fixing its mistakes (the likeliest time sink), the automatic snapping and checks of steps 4-5, and `report.md`. Expect longer if your plans are scans.

Done when: the model's overall dimensions match the printed dimensions within 1% (plans in scale mode A or B; in mode C that holds by construction, so check room areas against printed areas instead); every door and window sits where the overlay showed; and you can orbit it. No furniture, no textures, one default sun.
