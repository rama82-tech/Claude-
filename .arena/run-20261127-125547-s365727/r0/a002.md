# Build plan: 2D floor plan to 3D model

## Recommendation

Build a small Python pipeline in which **a vision-capable model reads the plan and writes a JSON description, and a deterministic script turns that JSON into geometry**. Do not use an AI image generator for the geometry, and do not train a CV model.

```
plan.png/pdf -> normalise -> Claude reads it -> plan.json -> you fix it -> build.py -> house.glb + preview PNGs
```

Everything runs in the Claude Code container with no GPU. The user gets a model they can open anywhere, and a JSON file they can edit by hand when the reading is wrong.

## Questions that decided the design

**What must be accurate?** Wall positions, room sizes and door and window positions. A render that merely looks like a house is not enough. Image generators cannot hold dimensions, and they invent walls and furniture. So geometry comes from code, never from a generator.

**Where does the hard part sit?** Reading the drawing. Classic CV (Hough lines, contour detection, wall-thickness heuristics) is fragile on scans, hatching, text and furniture symbols. A vision model reads a plan well enough to list rooms, walls, openings and the printed dimensions. Dimensions are printed as text, so OCR is not needed as a separate step.

**Can the reading be trusted?** No. Vision models misplace coordinates by a few percent and miss thin walls. So the design has a check step: the script draws the extracted walls over the original plan, and flags rooms whose computed area differs from any area printed on the plan. The human fixes the JSON and re-runs. This is cheaper than building a perfect extractor.

**Which 3D tool?** Options were Blender (via bpy or MCP), three.js, or a Python mesh library.
- Blender is heavy and needs an install or a live GUI session. It earns its place only for photoreal renders, so it is optional (stage 2).
- three.js is good for an interactive viewer, but exporting a file from it needs more plumbing.
- `trimesh` with `shapely` makes watertight meshes in pure Python, exports GLB/OBJ/STL, and runs headless.

The simplest choice is `trimesh` + `shapely` for the model, and a small `model-viewer` HTML page, rendered with the preinstalled Playwright/Chromium, for previews.

**What is the output?** `house.glb` (open in any viewer, Blender, or web), `house.obj`, an isometric PNG, a top-down PNG, and `plan.json`. A photoreal render is a later step, not part of the minimum.

## Pipeline

1. **Normalise the input.** PDFs are rasterised with `pymupdf` at 200 DPI. Images are deskewed and cropped to the drawing. Write down the original pixel size.
2. **Establish scale.** Ask the model for one or two printed dimensions with their pixel endpoints, for example "12'-6" along this wall". Compute `units_per_pixel`. If several dimensions disagree by more than 3 percent, warn. If no dimension is printed, require the user to give one number and stop otherwise. A scale bar is the fallback.
3. **Extract to JSON** (schema below). Prompt the model to return only JSON, in plan pixel coordinates, one wall per straight segment, with openings attached to a wall by an offset along it. Send the image at full resolution, and send a second zoomed call per quadrant if the plan is dense.
4. **Validate and snap.** Convert to metres. Snap endpoints that are within about 15 cm. Snap near-horizontal and near-vertical walls to axis-aligned. Check that every wall is part of a closed loop and every opening lies within its wall. Compare each room's computed area to any printed area. Write `overlay.png` showing the walls and openings over the plan.
5. **Human review.** Look at `overlay.png`, edit `plan.json`, re-run from step 4. Expect one or two rounds. This step is the main quality control.
6. **Build geometry** (`build.py`):
   - Walls: buffer each centreline by half its thickness with shapely, union them into one 2D footprint, and extrude to wall height (default 2.7 m). Unioning gives clean corners and junctions.
   - Openings: for each door or window, extrude a box through the wall and subtract it. A door spans floor to 2.1 m. A window spans sill 0.9 m to head 2.1 m. Do the subtraction with `manifold3d` (via trimesh) to avoid boolean failures.
   - Floors: each room polygon extruded 0.1 m, with a separate material per room type.
   - Ceiling: optional, off by default so top-down views work.
   - Materials: a flat PBR colour per type (walls off-white, floor wood or tile by room label, glass blue and transparent).
7. **Export and preview.** Write `house.glb` and `house.obj`. Render a top-down and an isometric PNG with Playwright loading `model-viewer` or three.js on a local HTML page, with a simple directional light plus ambient light and soft shadows.
8. **Optional photoreal stage.** Import the GLB into Blender (`bpy` headless, or the Blender MCP if the user has it running locally), add a sun and area lights, set Cycles samples to about 64, and render. This is not needed for the first version.

## `plan.json` schema (kept minimal)

```json
{
  "units": "m",
  "wall_height": 2.7,
  "walls":   [{"id":"w1","a":[0,0],"b":[5.2,0],"thickness":0.2}],
  "doors":   [{"wall":"w1","offset":1.0,"width":0.9}],
  "windows": [{"wall":"w1","offset":3.0,"width":1.2,"sill":0.9,"height":1.2}],
  "rooms":   [{"name":"Kitchen","type":"kitchen","polygon":[[0,0],[5.2,0],[5.2,4],[0,4]],"printed_area_m2":20.8}]
}
```

Walls are centrelines, so thickness is explicit. Curved walls, stairs, and multiple storeys are out of scope for version 1.

## Minimal first version

Roughly 250 lines of Python, built in one sitting:
- `pip install trimesh shapely manifold3d pymupdf pillow numpy` (and `playwright`, already present).
- `extract.py`: calls the model with the image and the schema prompt, saves `plan.json`.
- `check.py`: converts units, snaps, validates, writes `overlay.png`.
- `build.py`: the geometry in step 6, exporting `house.glb`.
- `preview.py`: Playwright screenshot of the GLB, top-down and isometric.

Acceptance test: use one simple rectangular plan with 4 rooms, 3 doors and 4 windows. The overall dimensions in the GLB must be within 2 percent of the printed ones, and every opening must be visible in the preview. Only after that works, try a messy scan.

If the extraction call is too much at first, hand-write `plan.json` for the test plan. The build half is useful and testable on its own.

## Accuracy: what makes it right

- Scale comes from printed dimensions, cross-checked against each other.
- Geometry is deterministic code, so the same JSON always gives the same model.
- Snapping and closed-loop checks remove most of the small errors from the vision reading.
- The overlay and area check show the user the errors instead of hiding them.
- Walls keep their real thickness through centreline buffering, so room interiors come out the right size.

## Risks and failure cases

| Risk | What happens | Mitigation |
|---|---|---|
| No printed dimensions | Model is the wrong size | Require one user-supplied dimension |
| Low-resolution or skewed scan | Walls misplaced | Deskew, upscale, run per quadrant |
| Furniture, hatching, or text read as walls | Phantom walls | Overlay review, plus a prompt that excludes furniture |
| Thin or merged walls, open plans | Missing walls | Manual JSON edit, area check |
| Doors drawn as arcs, sliding doors | Wrong opening type | Treat all as width plus offset; swing arc ignored |
| Boolean cut fails | Holes missing or broken mesh | Use manifold3d; check `mesh.is_watertight` |
| Several storeys, stairs, curves, sloped roofs | Not modelled | State out of scope; add per-storey JSON later |
| Model non-determinism | Different JSON each run | Save `plan.json` and treat it as the source of truth |
| Photoreal render invents furniture | Misleading | Only render the extracted geometry; do not use AI image generation on it |
| Plan is copyrighted or private | Data sent to a model | Use only plans the user may share |

## Later upgrades (only when needed)

1. Blender photoreal render and walkthrough video.
2. Furniture from room type, placed by a simple rule.
3. A web page where the user drags wall endpoints on the plan, replacing JSON editing.
4. A CV pre-pass (OpenCV line detection) to give the model candidate wall lines on very large plans.
5. Multi-storey support.

## Assumptions

- The input is a single-storey, mostly orthogonal residential plan with at least one printed dimension.
- "3D model" means a viewable and exportable file (GLB/OBJ), plus preview images, not a CAD or BIM file.
- A model with vision capability can be called from the session, and no GPU is available.
- Default wall height 2.7 m, wall thickness 0.2 m (0.1 m interior), door 0.9 x 2.1 m, window sill 0.9 m; all overridable in the JSON.
- The user will accept reviewing an overlay and editing the JSON to correct mistakes.
