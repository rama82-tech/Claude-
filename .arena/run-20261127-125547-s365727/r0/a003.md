# Floor plan to 3D: build plan

## Recommendation in one line

Do not generate the 3D model from the picture. Turn the picture into a small, checkable **JSON plan**, then build the 3D model from that JSON with a deterministic script. Everything else is optional.

## Why this shape (what usually fails, and what prevents it)

| Failure | Prevention in this design |
|---|---|
| AI image generators invent walls, drop rooms, ignore dimensions | No generator in the geometry path. Geometry comes only from numbers in the JSON. |
| Walls drift or have the wrong scale | The scale comes from one printed dimension, and every other printed dimension is checked against it. |
| Misread doors, windows or rooms go unnoticed | An overlay image draws the JSON on the original plan, and you approve it before any 3D is built. |
| Heavy toolchains (Blender, OpenCV, OCR, trained models) break in a container | The first version needs only Python, one pip package and the Chromium that is already installed. |
| Output cannot be opened or shared | The output is a standard GLB, a single HTML viewer and PNG renders. |
| Curved walls, scans and hand sketches defeat the extractor | Out of scope for v1. The tool refuses them (see Risks). |

## Assumptions

- Input is a clean, mostly orthogonal plan (PNG, JPG or PDF) with at least one printed dimension. If there are none, you give one measurement.
- One floor, flat roof, straight walls. Multi-storey is a later step.
- Claude (in your session) can look at the image. That is the "vision" step, so no OCR or computer-vision library is needed.
- "3D model" means a viewable, orbitable model plus still renders. It does not mean a BIM or CAD file.
- Units are metres internally.

## Architecture

```
plan.png/pdf --(1) read--> plan.json --(2) overlay check--> approved plan.json
                                                  |
                                    (3) build.py --> house.glb
                                                  |
                                    (4) viewer.html + Playwright --> renders/*.png
```

Four steps and three files you write. That is all of it.

### Step 1: Read the plan into plan.json

PDFs are converted to PNG first (`pdftoppm -r 200`). You show the image to Claude and have it fill in this schema. Claude is good at reading rooms and labels and bad at measuring pixels, so **make it copy printed dimensions and give wall positions in metres, not pixels.**

```json
{
  "units": "m",
  "wall_height": 2.7,
  "wall_thickness": 0.15,
  "walls":   [ {"id":"w1","from":[0,0],"to":[6.0,0]} ],
  "openings":[ {"wall":"w1","type":"door","at":1.2,"width":0.9,"height":2.1,"sill":0},
               {"wall":"w1","type":"window","at":3.5,"width":1.5,"height":1.2,"sill":0.9} ],
  "rooms":   [ {"name":"Kitchen","polygon":[[0,0],[6,0],[6,4],[0,4]],"floor":"tile"} ]
}
```

Rules that keep the JSON honest:
- Every printed dimension is copied into a `"stated"` list (for example `{"wall":"w1","length":6.0}`). The script checks that each wall length matches within 2 percent. A mismatch stops the build.
- Wall end points that should meet must be identical numbers. The script snaps endpoints within 5 cm and fails if a wall is left floating.
- Every opening must lie fully inside its wall (`at` plus half `width` less than wall length), or the build stops.

### Step 2: Overlay check (the human gate)

A 30-line script draws the walls, openings and room names from the JSON over the original image, using a scale taken from one stated dimension. You look at one picture. If it matches, continue. If not, tell Claude what is wrong ("the bathroom door is on the east wall") and regenerate the JSON. This one gate removes most errors, and it costs far less than any automated detector.

### Step 3: build.py makes house.glb

Library: `trimesh` (pure Python, `pip install trimesh shapely mapbox-earcut numpy`).

1. For each wall, make a box (length x thickness x height) centred on its line. For L- and T-junctions, extend each wall by half the thickness so corners close.
2. For each opening, cut it out of the wall by splitting the wall into pieces: left of the opening, right of it, a block above it, and for windows a block below it. This needs no boolean-engine dependency, and it fits axis-aligned openings, which is all v1 supports.
3. Add a thin glass pane in each window and a simple slab for each door leaf.
4. Triangulate each room polygon (shapely) into a floor, and add a ceiling if wanted.
5. Assign named materials by room `floor` value or by wall (a flat colour or a plain texture). Give every node a name (`wall_w1`, `floor_Kitchen`) so the model is inspectable.
6. Export `house.glb`.

Also write `report.txt`: wall count, total floor area per room, and the stated-versus-built dimension check. Floor areas you can cross-check against any areas printed on the plan.

### Step 4: Viewer and renders

`viewer.html` loads `house.glb` with three.js (pinned version from a CDN, or vendored locally) and offers orbit controls, a daylight light and soft shadows. A Playwright script opens it headless and saves `top.png` (orthographic top-down), `iso.png` (cutaway: hide walls facing the camera) and one eye-level image per room. Software WebGL in headless Chromium works for this, so add the flag `--use-gl=swiftshader` if the canvas comes out blank.

## Getting each element right

- **Walls**: from the JSON centre lines plus one global thickness. Use per-wall thickness only if the plan clearly shows thick external walls (default 0.25 m external, 0.10 m internal, as an optional field).
- **Openings**: always specified along a wall by position and width, never by pixel. Door default 0.9 x 2.1 m, window default sill 0.9 m and height 1.2 m, used only when the plan gives nothing.
- **Floors**: from room polygons, which also gives you labels and areas for free.
- **Materials**: a small lookup table (wood, tile, plaster, glass). Flat colours are fine for v1.
- **Lighting**: one sun light, one sky ambient, soft shadows. No lighting design in v1, and none is needed to judge layout.

## Outputs

`plan.json` (the source of truth), `overlay.png`, `house.glb`, `report.txt`, `renders/top.png`, `renders/iso.png`, `renders/room_*.png`, `viewer.html`. To change the model, edit the JSON and rerun. Nothing in the pipeline is edited by hand in a 3D tool.

## Minimal first version (an afternoon)

1. Take one simple rectangular plan with a printed dimension.
2. Hand-write (or have Claude write) its `plan.json`.
3. Write `build.py` with only wall boxes, door and window cutouts, and a floor.
4. Open `house.glb` in `viewer.html` and screenshot it with Playwright.
5. Add the overlay check and the dimension assertions.

Done when: three different plans go from image to GLB with every stated dimension matching and the overlay approved.

## Later additions (add one only when v1 exposes a need)

- Automatic wall detection (OpenCV line and contour extraction) to pre-fill the JSON, still passing through the overlay gate.
- OCR (Tesseract) to read dimensions, if Claude misreads them often.
- Blender (scripted, or via MCP) to import the GLB for photoreal Cycles renders, furniture and a walkthrough video.
- An AI image model for a decorative "photoreal" render of the finished model, kept separate and labelled as an illustration, never as geometry.
- Diagonal and curved walls, stairs, a second storey.

## Risks and failure cases

- **No printed dimensions**: the scale is a guess, so the tool asks for one measurement and refuses to build without it.
- **Low-quality scans, hand sketches, photos at an angle**: not supported in v1. The overlay will visibly fail, so you find out immediately.
- **Dimension strings that conflict** (rounded values, wall thickness included or excluded): the 2 percent check flags them. Decide whether dimensions are inside faces or centre lines and say so once in the JSON (`"dimension_basis": "inner"`).
- **Symbols misread** (swing arcs, sliding doors, stairs): swing direction is ignored in v1 (openings are cut, not animated).
- **Sloped or open-plan features, balconies, columns**: are not modelled. Columns may be added as extra boxes.
- **Headless rendering is slow or blank**: fall back to software GL, lower the resolution, or just ship the GLB and HTML viewer.
- **Model Claude's reading is wrong but plausible**: the overlay gate and the area report are the defences. Never skip them.
