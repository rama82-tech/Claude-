# Floor plan to 3D model: a build plan that survives real plans

## Recommendation

Do not go straight from the image to 3D. Go through a small, human-checkable **plan file** (JSON) in between:

```
image/PDF -> normalise + calibrate scale -> extract (vision model + CV cross-check)
          -> plan.json (walls, openings, rooms, scale) -> validate + repair
          -> deterministic geometry (Python) -> GLB/OBJ  -> Blender or three.js for materials, light, renders
```

Why this design: the failure that ruins this kind of project is a model that is almost right and wrong in ways you cannot see or fix, such as a wall 40 cm off, a door on the wrong side, or a room with no floor. The JSON stage gives you three things:

- **Checkable:** a 2D overlay of the JSON on the original image shows every error at a glance.
- **Editable:** one wrong number is a one-line fix, not a re-run.
- **Repeatable:** the same JSON always gives the same 3D, so geometry is never the unreliable part.

AI image generators are used only for optional beauty renders, never as the source of dimensions.

## Assumptions

- Input is a PNG, JPG, or a PDF page (vector or scanned). Quality varies, and the plan may be a phone photo.
- Dimensions are printed on the plan (feet-inches or metric). Some plans also have a scale bar.
- Residential, single storey first. Multi-storey is a later extension (one plan.json per level plus stacking).
- Walls are straight and mostly orthogonal in v1. Curves and angled walls are phase 2.
- Wall height defaults to 2.7 m (9 ft), door 2.1 m (6 ft 8 in), window sill 0.9 m, window head 2.1 m. These are overridable, and the plan rarely states them.
- Claude vision (the Claude Code session itself) is the primary reader. No GPU or model training is available.
- "Accurate" means within about 2% of printed dimensions, not surveyor grade.

## Edge cases first, and how the design handles each

| Case | What goes wrong | Design response |
|---|---|---|
| **No usable scale** (no dimensions, no bar) | Model is the right shape at the wrong size | Refuse to guess silently. Fall back to a stated default (a standard door is 0.9 m wide), mark the output `scale_source: "assumed_door"`, and put a warning in the report. |
| **Conflicting dimensions** (the chain adds up to 40'-0" but the overall says 40'-6") | Walls overshoot or gaps appear | Treat printed dimensions as constraints. Solve by least squares, and flag any residual above 2 cm to the user. Never silently pick one. |
| **Image is not to scale** ("NTS", or a sketch) | Pixel measurement is meaningless | Use only printed dimensions. Pixels give topology (which wall touches which), not length. |
| **Skewed or rotated photo, paper curl** | Scale varies across the image | Detect the page quad, apply a perspective warp, and deskew via the dominant wall angle. Reject if the residual keystone is too high and ask for a flatter photo. |
| **Scanned PDF vs vector PDF** | A vector PDF has exact line geometry, and a scan does not | Test with PyMuPDF `page.get_drawings()`. If there are many paths, parse lines directly (exact walls). Otherwise rasterise at 200 DPI. |
| **Walls drawn as double lines, hatching, or solid fill** | Skeleton extraction misreads thickness | Extract the wall **centreline plus thickness** into the JSON, never outline pixels. Support all three styles with a per-plan `wall_style` hint. |
| **Dashed lines, furniture, grid lines, hatching, dimension strings** mistaken for walls | Phantom walls | Mask text and dimension layers before wall detection (OCR boxes). Classify strokes by thickness histogram, and walls are the thickest cluster. |
| **Door swing arcs vs window symbols vs sliding doors** | Wrong opening type or hinge side | Each opening has `type`, `width`, `host_wall`, `offset`. Arcs map to swing doors, three parallel lines to windows, an offset double line to sliding doors. Ambiguous ones are listed in the report for confirmation. |
| **Openings with no printed width** | Default width wrong | Use the type default (door 0.9 m, window 1.2 m), but flag the opening as `width_source: "default"`. |
| **Small wall gaps, T-junctions, walls that do not quite meet** | Floor polygons do not close and rooms are missing | Snap endpoints within a tolerance (about 5 cm scaled), then build rooms with `shapely.polygonize`. Any unclosed loop is reported with its coordinates. |
| **Open-plan, no wall between kitchen and living** | A room-detection algorithm finds one big room | Allow virtual boundary segments (`type: "virtual"`) that make a room edge with zero height. |
| **Curved or angled walls, bay windows** | v1 geometry cannot represent them | Reject cleanly: "curved wall at (x,y) approximated as N segments" with a polyline approximation, and say so. |
| **Different wall thicknesses** (exterior 20 cm, interior 10 cm) | Uniform thickness misaligns openings | Thickness is per wall. |
| **Stairs, columns, fireplaces, built-ins** | Ignored or turned into walls | Stairs become a simple box-run placeholder with a warning. Columns are optional `columns[]`. Everything else is skipped and listed. |
| **Text OCR errors** (`9'-6"` read as `96"`, `l`/`1`, metric vs imperial) | Order-of-magnitude errors | Parse with a strict grammar and a unit-system vote across all labels. A dimension more than 3x the median of others is rejected and queued for review. |
| **Multiple plans on a sheet** (ground, first floor, site plan, legend) | Wrong region modelled | Detect regions and pick one by user choice (default: the largest). Never merge regions. |
| **Very large plans, high-res scans (>20 MP)** | Vision model downsamples and loses text | Tile at 2x2 with overlap for reading dimensions, and use the full image for layout. |
| **Boolean failures on overlapping walls** | Corrupt mesh, holes | Union walls in 2D with shapely first, then extrude. Cut openings from the extruded solid with the `manifold3d` engine. Check `mesh.is_watertight` in tests. |
| **Plan is unreadable or not a plan** | Garbage out | A confidence gate. If fewer than 4 closed walls are found, stop and report instead of fabricating a house. |

## Pipeline, stage by stage

### 0. Ingest and normalise
- PDF: PyMuPDF. Prefer vector paths. Otherwise render at 200 to 300 DPI.
- Image: OpenCV, with grayscale, perspective correction if a page quad is found, deskew by the Hough dominant angle, and light denoise.
- Save `normalised.png` plus the transform, so every later coordinate maps back to the original.

### 1. Scale calibration (do this before anything else)
Priority order, and record which won:
1. Printed overall or chain dimensions matched to their dimension lines (best).
2. A scale bar with a known length.
3. A stated ratio (1:100) combined with the PDF's physical page size.
4. A standard door width (0.9 m), which is a last resort and is always flagged.

Compute pixels per metre from several dimension pairs and report the spread. A spread above 3% means the plan is distorted or misread, so go to review.

### 2. Extraction into plan.json
Run two readers and compare them, because disagreement shows where the errors are:
- **Reader A (Claude vision):** given the image, tiles, and the schema below, it returns walls, openings, room labels, and dimensions as JSON. It is good at semantics ("that arc is a door swing").
- **Reader B (classical CV):** OpenCV morphology and line detection (`cv2.HoughLinesP`, `cv2.ximgproc.thinning`), or exact paths from a vector PDF. It is good at precise coordinates.
- **Merge rule:** semantics from A, coordinates snapped to B's nearest detected line within 10 cm. A wall found by only one reader is kept but marked `confidence: low`.
- OCR (`pytesseract` or `easyocr`) provides dimension text. Claude vision can cross-check any value that OCR and the grammar disagree on.

### 3. The plan file

```json
{
  "units": "m",
  "scale": {"px_per_m": 118.4, "source": "dimension_chain", "spread_pct": 1.1},
  "default_height": 2.7,
  "walls": [
    {"id": "w1", "a": [0,0], "b": [8.2,0], "thickness": 0.2, "kind": "exterior"},
    {"id": "w2", "a": [4.1,0], "b": [4.1,5.0], "thickness": 0.1, "kind": "interior"}
  ],
  "openings": [
    {"id": "d1", "type": "door", "wall": "w2", "offset": 1.0, "width": 0.9,
     "height": 2.1, "sill": 0, "swing": "left", "width_source": "default"},
    {"id": "n1", "type": "window", "wall": "w1", "offset": 2.0, "width": 1.5,
     "height": 1.2, "sill": 0.9, "width_source": "printed"}
  ],
  "rooms": [{"id": "r1", "label": "Kitchen", "floor": "tile"}],
  "warnings": []
}
```

Coordinates are metres, origin at the bottom-left of the outer bounding box, y up. Every value that was not read from the plan carries a `*_source` so the report can list guesses.

### 4. Validate and repair (the quality gate, in code)
Checks that must pass or produce a named warning:
1. Every opening lies within its wall: `offset + width <= length`, and openings do not overlap each other.
2. Endpoints snap within tolerance, and no wall has length under 0.3 m.
3. Rooms polygonise. Count unclosed loops.
4. Total footprint area is within 5% of any printed area figure.
5. Printed dimensions versus computed lengths: residual below 2 cm, else flagged.
6. Overlay render: draw plan.json over the source image to `overlay.png` and look at it. This is the human check, and it takes under 10 seconds per plan.

### 5. Geometry (deterministic Python)

```python
import json, numpy as np, trimesh
from shapely.geometry import LineString, box
from shapely.ops import unary_union, polygonize

plan = json.load(open("plan.json"))
H = plan["default_height"]

# 2D wall footprint: flat-capped buffers union cleanly, with square corners
foot = unary_union([
    LineString([w["a"], w["b"]]).buffer(w["thickness"]/2, cap_style=2, join_style=2)
    for w in plan["walls"]
])
walls = trimesh.creation.extrude_polygon(foot, H)      # handles MultiPolygon via list

# openings: subtract thin boxes through the wall at the right offset
byid = {w["id"]: w for w in plan["walls"]}
for o in plan["openings"]:
    w = byid[o["wall"]]
    a, b = np.array(w["a"]), np.array(w["b"]); L = np.linalg.norm(b-a)
    u = (b-a)/L; c = a + u*(o["offset"] + o["width"]/2)
    cut = trimesh.creation.box(extents=[o["width"], w["thickness"]*3, o["height"]])
    ang = np.arctan2(u[1], u[0])
    T = trimesh.transformations.rotation_matrix(ang, [0,0,1])
    T[:3,3] = [c[0], c[1], o["sill"] + o["height"]/2]
    cut.apply_transform(T)
    walls = walls.difference(cut, engine="manifold")

# floors from closed wall loops
rooms = list(polygonize(unary_union([LineString([w["a"], w["b"]]) for w in plan["walls"]])))
floors = [trimesh.creation.extrude_polygon(r, 0.1).apply_translation([0,0,-0.1]) for r in rooms]
assert walls.is_watertight, "wall mesh not watertight"
trimesh.Scene([walls, *floors]).export("house.glb")
```

Notes: window glass and door leaves are added as thin separate meshes in the opening, so materials can be assigned later. Ceiling is optional, and is off for top-down renders. Install `manifold3d` (`pip install trimesh shapely manifold3d pymupdf opencv-python`).

### 6. Materials and lighting
- Per-object material names (`wall_ext`, `wall_int`, `floor_<room>`, `glass`, `door`) so any renderer can re-skin them.
- Default look: matte white walls, light-wood or tile floors by room label (bathroom, kitchen get tile), and transparent glass with 0.05 roughness.
- Lighting presets:
  - **Daylight:** a sun lamp plus sky (Blender Nishita sky, or three.js `Sky`), with window openings letting light in.
  - **Clay:** a white material and soft world light. This is best for checking geometry, since it hides texture distractions.
  - **Evening:** warm point lights per room centroid.
- Do not rely on global illumination for correctness. It only affects looks.

### 7. Rendering paths (pick by need)
| Path | Use | Cost |
|---|---|---|
| **three.js + Playwright** (Chromium is already installed) | Fastest. Interactive viewer, a top-down PNG, an orbit turntable via screenshots | Free, runs headless here |
| **Blender headless** (`blender -b -P build.py`) | Photoreal Cycles renders, cutaway, walkthrough MP4 | Needs a Blender install, and slower. On CPU, use low samples with a denoiser |
| **Blender via MCP** | Interactive editing with the user | Needs the user's desktop Blender, so not available in this cloud container |
| **AI image generator** | Pretty marketing renders from the clay render as a control image | Dimensions drift, so label it "illustrative" |

### 8. Output files
- `plan.json` (the source of truth) and `report.md` (scale source, guesses, warnings).
- `overlay.png`, the proof the extraction matches.
- `house.glb` (primary), plus `house.obj` or `.fbx` for other tools, and `house.blend` if Blender is used.
- Renders: `top.png`, `iso_cutaway.png`, `room_<name>.png`, and optional `turntable.mp4`.

## Risks that remain

1. **Vision-model coordinate imprecision.** Mitigated by CV snapping and the overlay check, but a faint plan can still fail. Fall back to a manual-correct loop on plan.json.
2. **Hand-drawn plans** break the CV reader. Rely on Claude vision plus printed dimensions only, and warn that accuracy is lower.
3. **Hosting:** Blender may not be installable in the container (network rules, or no GPU). The Python plus three.js route does not need it, so build that first.
4. **Boolean engine availability.** If `manifold3d` fails to install, fall back to building wall segments between openings (split each wall into pieces with a lintel and a sill block). It is more code but needs no boolean.
5. **Legal and privacy.** Plans may contain addresses. Keep processing local and do not upload them to third-party render services without telling the user.
6. **Scope creep** into furniture, stairs, multi-storey. Keep them out of v1.

## Minimal first version (a day or two of work)

Scope: one rectilinear single-storey plan, **vector PDF or a clean image**, dimensions given, **no CV, no OCR**.

1. Claude reads the image and writes `plan.json` by hand, following the schema above (this replaces stages 1 to 2).
2. `validate.py` runs checks 1, 2, 3 and 6 (overlay), and prints warnings.
3. `build.py` (the geometry code above) produces `house.glb`.
4. `viewer.html` loads the GLB in three.js, with `OrbitControls`. Playwright takes `top.png` and `iso.png`.
5. A one-page `report.md` lists scale source, guesses, and warnings.

Done when: on 3 sample plans (a clean box, an L-shape with 4 rooms, a plan with a door on every wall), wall lengths are within 2% of printed values, the GLB is watertight, and the overlay visibly matches.

Then add, in order: (a) OCR plus the dimension solver, (b) CV wall snapping, (c) PDF vector parsing, (d) Blender renders, (e) AI-image beautification, (f) multi-storey.

## Test checklist for each plan

- [ ] `scale.source` is printed dimensions, not a default.
- [ ] Every printed dimension reproduced within 2 cm.
- [ ] No room missing a floor, no opening floating in space.
- [ ] Mesh watertight, and door and window counts equal the counts on the plan.
- [ ] Overlay checked by eye, and the guesses in `report.md` read and accepted.
- [ ] Clay render looks like the plan when rotated to the plan's orientation.
