# Turning a 2D floor plan into a 3D model: build plan

## Recommendation in one paragraph

Do not go straight from pixels to 3D. Go **plan image -> a small, human-checkable JSON description (walls, openings, rooms, scale) -> deterministic geometry code -> GLB file -> renders**. Claude's vision reads the plan into the JSON, a short check script draws the JSON back over your image so you can see mistakes in seconds, and plain Python (or Blender) turns the JSON into a model. The JSON is the product: it is the one place where accuracy is decided, and it is cheap to correct by hand. AI image generators are an optional last step for pretty pictures, never the source of geometry.

## Assumptions

- Input is one floor of a residential plan as PNG/JPG/PDF, drawn roughly to scale, with at least one printed dimension (e.g. `30'-0"`) or a scale bar. Mostly straight, orthogonal walls. Curved walls, stairs, and multi-storey buildings are out of scope for v1.
- You are in the Claude Code cloud container: Python 3, Node, Chromium and Playwright present. I assumed Blender is **not** installed and that a headless GPU is not available. The geometry and the JSON were tested in a fresh Python venv (`shapely`, `trimesh`, `numpy`, `scipy`); the Blender and three.js parts below are described but not run here.
- "3D model" means: a file you can orbit in a browser, open in Blender, and render stills from. It is not a construction-grade BIM model.
- Default heights and thicknesses are used when the plan does not give them: wall 2.7 m (8'-10"), exterior wall 8" (0.2032 m), interior wall 4.5" (0.1143 m), door head 2.1 m, window sill 0.9 m and head 2.1 m. These are stated in the JSON so you can change them.

## A worked example (the numbers everything else is built on)

A 2-bedroom unit, 30'-0" x 24'-0", image 1200 x 960 px. Printed dimension line `30'-0"` runs from x=100 px to x=1100 px, and `24'-0"` runs from y=80 px to y=880 px.

1. **Scale.** 1000 px = 30 ft, so 33.33 px/ft = 0.009144 m/px. Cross-check: 800 px / 24 ft = 33.33 px/ft. Identical, so the image is not stretched. (If the two differ by more than about 2%, the scan is skewed or non-uniform; stop and warn rather than guess.) Sanity checks that fall out for free: a 3'-0" door should be about 100 px wide, a 6" wall about 17 px thick.
2. **Coordinates.** Pixel to metre: `x = (px - 100) * 0.009144`, `y = (880 - py) * 0.009144` (flip y so +y is up on the plan). Everything is stored in metres, wall **centrelines**, origin at the lower-left corner.
3. **Walls.** Four exterior walls (centreline rectangle 9.144 x 7.3152 m), one full-height interior wall at x = 18'-0" = 5.4864 m, one short interior wall at y = 12'-0" = 3.6576 m running east from it.
4. **Openings.** Each opening is attached to a wall by `at` (distance along the wall to the opening centre), width, sill height and head height. Example: front door `D1` on the south wall, centre 9'-0" = 2.7432 m from the start, 3'-0" wide, 0 to 2.1 m high. Window `N1`, 5'-0" wide, sill 0.9 m, head 2.1 m, on the north wall.
5. **Rooms** are not drawn by hand. They are found by polygonizing the wall centrelines; the JSON only gives a label point and a floor material per room.
6. **Result of running the script below on this JSON:** 17 mesh pieces, every piece watertight, bounding box 9.35 x 7.52 m, wall top at 2.7 m, clear floor areas Living 37.9 m2 (408 sq ft), Bed 1 and Bed 2 12.2 m2 (132 sq ft) each. These match a hand check: the living room is 18' x 24' = 432 sq ft centreline-to-centreline, minus the half-thickness of the surrounding walls.

### The generator (`build.py`), exactly what was tested

```python
import json, sys, numpy as np, trimesh
from shapely.geometry import LineString, Point, Polygon, box
from shapely.ops import unary_union, polygonize
from shapely import affinity

def build(plan, out):
    H = plan["wall_height"]
    W = {w["id"]: w for w in plan["walls"]}
    ext = []
    for w in plan["walls"]:
        a, b = np.array(w["a"]), np.array(w["b"]); d = (b-a)/np.linalg.norm(b-a)
        ext.append(LineString([a-d*w["t"]/2, b+d*w["t"]/2]).buffer(w["t"]/2, cap_style="flat"))
    foot = unary_union(ext)
    cutters = {}
    for o in plan["openings"]:
        w = W[o["wall"]]; a, b = np.array(w["a"]), np.array(w["b"])
        d = (b-a)/np.linalg.norm(b-a); c = a + d*o["at"]
        r = box(-o["w"]/2, -w["t"]/2-0.01, o["w"]/2, w["t"]/2+0.01)
        r = affinity.rotate(r, np.degrees(np.arctan2(d[1], d[0])), origin=(0,0))
        cutters[o["id"]] = affinity.translate(r, c[0], c[1])
    allcut = unary_union(list(cutters.values()))
    meshes = []
    def ext_poly(poly, z0, z1, name, color):
        polys = [poly] if poly.geom_type == "Polygon" else list(getattr(poly, "geoms", []))
        for p in polys:
            if p.geom_type != "Polygon" or p.area < 1e-6: continue
            m = trimesh.creation.extrude_polygon(p, z1 - z0)
            m.apply_translation([0, 0, z0]); m.visual.face_colors = color
            meshes.append(m)
    wc = [235,232,225,255]
    ext_poly(foot.difference(allcut), 0, H, "walls", wc)
    for o in plan["openings"]:
        piece = foot.intersection(cutters[o["id"]])
        if o["sill"] > 0: ext_poly(piece, 0, o["sill"], o["id"]+"_sill", wc)
        ext_poly(piece, o["head"], H, o["id"]+"_head", wc)
    lines = unary_union([LineString([w["a"], w["b"]]) for w in plan["walls"]])
    floors = {"oak":[176,140,98,255], "carpet":[150,150,160,255]}
    for r in polygonize(lines):
        lab = next((q for q in plan["rooms"] if r.contains(Point(q["at"]))), None)
        fl = r.difference(foot)
        print(f"room {lab['label'] if lab else '?'}: clear floor {fl.area:.2f} m2 = {fl.area*10.7639:.0f} sq ft")
        if lab: ext_poly(fl, -0.1, 0, "floor", floors[lab["floor"]])
    ext_poly(Polygon(foot.exterior), -0.2, -0.1, "slab", [120,120,120,255])
    trimesh.Scene(meshes).export(out)
    return meshes

if __name__ == "__main__":
    plan = json.load(open(sys.argv[1])); meshes = build(plan, sys.argv[2])
    print("meshes", len(meshes), "watertight", all(m.is_watertight for m in meshes))
    print("bounds", trimesh.util.concatenate(meshes).bounds.round(3).tolist())
```

Run: `python build.py plan.json house.glb`. Key design choice: instead of boolean-subtracting door and window boxes from solid walls (which needs a robust boolean library and fails on degenerate input), the code works in **2D with shapely**. It unions all wall rectangles into one footprint (so T and L joints merge cleanly with no overlapping faces), subtracts the opening rectangles, extrudes the remainder to full height, then extrudes the small piece above each door/window (head to ceiling) and below each window (floor to sill). The glass, frames, and door leaves are added later as separate objects.

## Architecture

```
plan.png/pdf
   |
[1 Prepare]  render PDF page at 200-300 dpi, deskew, crop, find scale
   |
[2 Read]     Claude vision + OCR + OpenCV -> plan.json (draft)
   |
[3 Verify]   overlay plan.json on the image -> overlay.png; run rule checks; you correct JSON
   |
[4 Build]    build.py -> house.glb (+ house.obj / .blend later)
   |
[5 View]     three.js viewer page, orbit + section; Playwright screenshots
   |
[6 Render]   (optional) Blender Cycles / EEVEE stills and walkthrough; (optional) AI polish
```

### Tools, and why each one

| Job | Use | Why |
|---|---|---|
| Reading the plan | Claude vision on the image, plus a crop-and-zoom loop for dense areas | Understands plan symbols (door swings, window glyphs, labels) that classical CV does not |
| Dimensions / text | `pytesseract` or `easyocr` for the numbers; PyMuPDF for PDFs with real text | Vector PDFs often contain the dimension text exactly. Extract it instead of OCRing it |
| Line geometry | OpenCV (`cv2`): threshold, `HoughLinesP`, morphological close, contours | Snaps Claude's rough coordinates to real wall lines and measures wall thickness in pixels |
| Verification | Pillow draw of JSON over the image | The cheapest, highest-value step in the whole project |
| Geometry | `shapely` + `trimesh` (v1); Blender `bpy` (v2) | Pure Python, installs with pip, no GPU, fully scriptable |
| Viewing | three.js `GLTFLoader` + `OrbitControls`, Playwright screenshot | Chromium is already in the container |
| Photoreal renders | Blender headless (`blender -b -P render.py`), Cycles on CPU or EEVEE | Real materials, sun/sky, interior lights. Or drive a live Blender through its MCP add-on if you have it on your own machine |
| Optional polish | An AI image generator used as an image-to-image "make this render look photographic" pass | Looks good but invents details, so label it as artwork |

## Step-by-step pipeline

1. **Normalise the input.** PDF: if it has a text layer, extract text and line vectors with PyMuPDF first; rasterise at 200-300 dpi only for vision. Photo or scan: deskew with a Hough-based angle estimate, crop to the drawing. Reject images where the two printed dimensions disagree by more than 2%.
2. **Calibrate scale.** Preferred order: (a) two printed dimension lines on perpendicular axes (as above, gives a consistency check); (b) a scale bar; (c) a known object (standard 3'-0" door) as a fallback, flagged as low confidence; (d) refuse and ask. Never use "1/4" = 1'" from the title block unless the DPI of the source is known.
3. **Extract the draft JSON.** Ask the vision model for walls as centreline segments in **pixel** coordinates, and openings as (wall, pixel position, pixel width, type). Convert to metres in code, not in the model's head. Do it per quadrant at higher zoom if the plan is dense.
4. **Snap and clean (code, not AI).**
   - Snap endpoints that are within about 1.5x the wall thickness to each other.
   - Snap near-horizontal and near-vertical segments to exactly horizontal/vertical when within 2 degrees.
   - Merge collinear segments; split walls where another wall T-joins them.
   - Round positions to 1 inch (0.0254 m); architects dimension to inches, so this removes drawing noise.
   - Replace measured widths with standard values when within tolerance (door 2'-6", 2'-8", 3'-0"; wall 4.5", 6", 8").
5. **Verify visually.** Draw walls in red, door openings in green, windows in blue, room labels, and each wall's id on top of the original image; look at it. Run automatic checks: every room polygon closed; no wall shorter than the wall thickness; every opening fits inside its wall with at least 0.1 m of solid wall at each end; every room has at least one door or opening; total area vs. any printed area on the plan within 3%.
6. **Build geometry** with `build.py`. Z-levels: slab -0.2 to -0.1 m, floors -0.1 to 0 m, walls 0 to 2.7 m. Ceiling: a slab per room at 2.7 m, hidden in the top-down view (or leave it out for cutaway views).
7. **Add openings' furniture.** Door leaf: a thin box 0.04 m thick, rotated about the hinge side to 0 or 90 degrees (read the swing arc from the plan if present). Window: frame (4 thin boxes) and a glass pane with a transparent material. Add 0.03 m reveal if you want shadows inside the opening.
8. **Materials.** Name every mesh by role (`wall_ext`, `wall_int`, `floor_Living`, `glass`, `door`), then map roles to materials from the room labels: oak for living, tile for bath and kitchen, carpet for bedrooms; white paint walls; slightly darker exterior. In v1 these are flat PBR colours exported in the GLB; in v2 swap in CC0 texture sets (Poly Haven, ambientCG) in Blender.
9. **Lighting.**
   - Browser viewer: one directional "sun" with shadows, a hemisphere light, soft ambient.
   - Blender: Nishita sky and a sun at a chosen time and north angle; area lights or emissive panels in windows for interiors; Cycles with 128-256 samples and denoising for stills. The north angle is rarely on the plan, so default it and expose it as one parameter.
10. **Export and render.** `house.glb` for the web, `house.blend` and `house.obj`/`.fbx` for editing, and three stills: top-down cutaway, isometric cutaway (remove the north and east walls or lower them to 1.2 m), one eye-level view per main room. Optionally a 20-second turntable or walkthrough from Blender.

## Getting the geometry accurate

- **Single source of truth.** All numbers live in the JSON in metres with named walls. If a wall is wrong you fix one line, not regenerate a model.
- **Centreline model.** Wall thickness is a property, not geometry the AI has to draw. Corners and T joints come from the shapely union, so they are always closed with no gaps or double faces.
- **Prefer printed numbers to measured pixels.** If the plan prints "12'-0"" between two walls, use that; use pixel measurement only to fill in what is not printed. Reconcile the chain: if printed room widths do not add up to the overall dimension, report the difference instead of silently picking one.
- **Show the error.** Output `report.md` with per-room printed area vs. computed area, and any opening that moved more than 3 inches in snapping.
- **Walls are drawn double-line.** Many plans draw each wall as two parallel lines (or a filled black band). Detect the pair, take the midline as centreline and the gap as the thickness. Single-line "centreline" plans give you only the default thickness.

## Trade-offs I chose (and what each costs you)

| Choice | I chose | Gives up |
|---|---|---|
| Read plan with vision + JSON review, vs. a trained wall-segmentation model | Vision + review | Not fully automatic, you look at one overlay per plan. In return: no training data, works on any drawing style, and every error is visible and fixable. A trained model (CubiCasa5k-style) is faster per plan but fails on drawings unlike its training set and cannot read dimensions |
| Python shapely/trimesh first, Blender second | Python first | No photoreal render in v1. In return: `pip install` works in the container, tests run in seconds, and the JSON-to-geometry code is reused unchanged by Blender later |
| 2D footprint extrusion, vs. boolean cuts in Blender | 2D extrusion | Cannot do arched openings, sloped ceilings, or chamfered reveals without extra work. Cheap, robust, no boolean failures |
| Metric centrelines, rounded to 1 inch | Yes | Real walls that are not on an inch grid (old buildings) are off by up to half an inch |
| AI image generation for renders | Optional last step only | Inconsistent between runs, invents rooms and furniture, cannot be measured. Fine for a mood image, wrong for anything a person will build from |
| One storey, orthogonal walls | Yes | Stairs, curved walls, angled walls and multiple floors need v2 work |

## Risks and failure cases

| Failure | What happens | Mitigation |
|---|---|---|
| No dimensions on the plan, or only room names | Scale unknown, model could be 30% off | Fall back to door width (flagged low confidence), or stop and ask |
| Photo of a paper plan: perspective or curved page | Skew, scale varies across the page | Four-point perspective correction before step 2; reject if the two printed dimensions disagree by more than 2% |
| Dense or low-resolution scans, hatching, furniture, text over walls | Furniture lines taken as walls | Crop and zoom in the vision pass; ask for walls only; reject segments shorter than 0.3 m not touching another wall |
| Door swing arcs and window glyphs mistaken for walls or each other | Wrong openings | Rule: openings must sit on a wall; arcs are never walls |
| Walls drawn as a solid black fill | Thickness measured, centreline hidden | Skeletonise (`skimage.morphology.skeletonize`), or distance-transform midline |
| Curved or diagonal walls | Orthogonal snapping flattens them | Turn snapping off per wall if the angle is not within 2 degrees of an axis; v1 accepts straight diagonals, not curves |
| Open-plan: no wall between kitchen and living | Room polygonize merges them | Add an invisible "room divider" segment with thickness 0 for labelling |
| Plan has several floors or elevations on one sheet | Mixed scale, wrong page | Detect and crop each drawing; ask which floor |
| Windows have no sill/head info | Default 0.9 / 2.1 m used | Default is stated in the report, easy to override |
| Vision model hallucinates a coordinate | A wall in the wrong place | Overlay review is mandatory in v1; never skip it |
| Plan is a copyrighted or confidential drawing | Sharing risk | Process locally in the container; do not publish the plan image |
| Blender not installable in the container | No photoreal stills | Keep the three.js + Playwright path as the default; do Blender renders on your own machine |

## Minimal first version (one to two days)

Goal: one image in, one orbitable GLB and two PNGs out, for a single-storey orthogonal plan with at least one printed dimension.

1. `pip install shapely trimesh numpy scipy mapbox-earcut pillow opencv-python-headless`.
2. Provide the plan image. Ask Claude to extract `plan.json` (pixel coordinates, then your code converts to metres using the printed dimension).
3. `overlay.py`: draw the JSON on the image with Pillow; look at it; correct the JSON.
4. `build.py` (above) -> `house.glb`.
5. `viewer.html`: three.js with `GLTFLoader`, `OrbitControls`, a sun, and a hemisphere light.
6. `shot.py`: Playwright opens the viewer, screenshots a top-down and an isometric view.

Done when: the generated model's overall dimensions are within 1% of the printed dimensions; every door and window appears in the position the overlay showed; and you can orbit it in a browser. This version has no furniture, no textures, and one default sun. It is small enough that you can see whether the idea works before spending on Blender.

**Next in order of value:** (1) automatic snapping and rule checks, (2) door leaves, window frames and glass, (3) Blender headless render script with materials and sky, (4) multi-storey, (5) the trained-model path if you will process hundreds of plans.
