# Floor plan to 3D model: a build plan that survives real plans

## Recommendation

Do not go straight from the image to 3D. Go through a small, human-checkable **plan file** (JSON) in between:

```
image/PDF -> normalise + calibrate -> extract walls/openings/rooms/dimensions
          -> plan.json -> validate + overlay -> deterministic geometry (Python)
          -> GLB (+ cutaway GLB) -> three.js / Blender for light and renders
```

The failure that ruins this kind of project is a model that is almost right in ways you cannot see: a wall 40 cm off, a door on the wrong side, a room with no floor. The JSON stage makes the result:

- **Checkable:** plan.json is drawn back over the original image (`overlay.png`), so every error is visible.
- **Editable:** one wrong number is a one-line fix, not a re-run.
- **Repeatable:** the same JSON always gives the same 3D.

AI image generators are used only for optional "illustrative" beauty renders, never as a source of dimensions.

## Assumptions

- Input is a PNG, JPG, or a PDF page (vector or scanned), possibly a phone photo.
- Dimensions are printed on the plan (feet-inches or metric). Some plans have a scale bar.
- Residential, single storey, straight and mostly orthogonal walls in v1. Curves, angled walls and multi-storey come later.
- Defaults when the plan is silent: wall height 2.7 m, door 2.1 m high and 0.9 m wide, window sill 0.9 m, window height 1.2 m, window width 1.2 m. All are overridable and are logged as guesses.
- Claude Code itself can view images (it is the primary reader in v1). No GPU, no model training.
- "Accurate" means within about 2 cm or 1% of printed dimensions, whichever is larger (feet-inches plans round to 1/2 inch, which is 1.3 cm), not surveyor grade. Accuracy comes from the **printed dimensions** (solved in stage 2b), not from pixel reading, which is only good for topology and rough position.
- This container (checked): `pip install` works for trimesh, shapely, manifold3d and mapbox-earcut, `npm i three` works, `/usr/bin/google-chrome` exists, the Python `playwright` package imports, but Playwright's own bundled browser download is absent (so launch the system Chrome, with a fallback chain in `shot.py`), and Blender is not present. Re-check these in your own container in the smoke test, since images differ.

## Edge cases first, and how the design handles each

| Case | What goes wrong | Design response |
|---|---|---|
| **No usable scale** | Right shape, wrong size | Fall back to a standard door (0.9 m), set `scale.source: "assumed_door"`, and put a warning at the top of the report. Never silent. |
| **Dimension basis** (printed room sizes are inside-face to inside-face, overall sizes are outside-face) | A centreline check gives false flags on correct plans, or "fixes" correct walls by half a wall thickness | Every dimension records the two walls it spans and a `basis` per end (`inside`, `outside` or `centre`). The checker converts centreline coordinates using half the wall thickness. A 4.00 m inside-width room with 0.2 m walls is 4.20 m between centrelines and passes. |
| **Conflicting dimensions** (chain adds to 40'-0", overall says 40'-6") | Overshoot or gaps | Report residuals per dimension. v1 never auto-shifts walls. Phase 2 runs least squares over centreline coordinates using the same basis offsets, and still lists every residual over 2 cm. |
| **Not to scale** ("NTS", sketch) | Pixel measurement is meaningless | Use printed dimensions only. Pixels give topology (what touches what), not length. |
| **Skewed or rotated photo, paper curl** | Scale varies across the image | Find the page quad, apply a perspective warp, deskew by the dominant wall angle. If calibration anchors disagree by more than 3%, stop and ask for a flatter photo. |
| **Scanned vs vector PDF** | A vector PDF has exact lines | `page.get_drawings()` in PyMuPDF. Many paths means parse lines directly. Otherwise rasterise at 200 DPI. |
| **Wall drawing styles** (double line, hatch, solid fill) | Outline pixels read as thin walls | Always extract centreline plus thickness. Double lines are paired (parallel, gap within 5 to 40 cm) and the midline is used. Solid fill uses skeleton plus distance transform for thickness. |
| **Furniture, grid lines, dashed lines, dimension strings** | Phantom walls | Mask OCR/text boxes first. Walls are the thickest stroke cluster. |
| **Door arcs, windows, sliding doors** | Wrong type or hinge | Openings store `type`, `width`, `wall`, `offset`, `swing`. Arc means swing door, three parallel lines means window. Ambiguous ones go in the report. |
| **Openings with no printed width** | Wrong width | Use the type default and mark `width_source: "default"`. |
| **Opening near a T-junction or corner** | The cut notches the perpendicular wall | Build step rejects any opening whose footprint touches another wall (tested), and the report names the opening. |
| **Gaps, T-junctions, near-miss walls** | Floors do not close | Snap endpoints within about 5 cm, then polygonize. Unclosed loops are reported with coordinates. |
| **Open plan** (kitchen and living share a space) | One big room or a solid wall built across it | `kind: "virtual"` walls take part in room polygons but are never extruded (tested). |
| **Disconnected wall groups** (garage, one unsnapped wall) | A MultiPolygon crashes extrusion | Every polygon is extruded in a loop (tested with a detached wall). |
| **Different thicknesses** | Misaligned openings | Thickness is per wall. |
| **Curved or angled walls, bay windows** | v1 cannot represent them | Approximate as short straight segments and say so in the report. |
| **Stairs, columns, built-ins** | Ignored or built as walls | Stairs become a box placeholder with a warning. Anything else is skipped and listed. |
| **OCR errors** (`9'-6"` read as `96"`, `l`/`1`) | Order-of-magnitude errors | Strict grammar, a unit-system vote, and reject any value more than 3x the median. |
| **Multiple plans on one sheet** | Wrong region | Detect regions, ask the user (default: largest). Never merge. |
| **Very large scans (>20 MP)** | Text is lost on downsampling | Read dimensions from 2x2 overlapping tiles and layout from the full image. |
| **Boolean failures** | Corrupt mesh | Union walls in 2D first, then extrude, then cut with `manifold3d`. Assert watertight (tested). |
| **Not a plan or unreadable** | Garbage out | If fewer than 4 closed wall segments are found, stop and report. |
| **Axis convention** (plan is Z-up, glTF is Y-up) | A GLB written Z-up opens on its side in Blender, model-viewer and every other glTF tool | `build.py` rotates -90 degrees about X before export, so the file is true glTF (Y up). The viewer then uses the standard Y-up camera. Blender's importer converts it back to Z-up. Tested: an L-shaped extrusion exports with bounds y in [0, 2.7] and renders the right way round. |
| **Low cutaway height** (0.9 m or 0.6 m cut, below window sills) | Zero or negative cutter box, exception | Openings whose sill is at or above the cut height are skipped and logged. Others are clamped. Not yet run end to end: the checklist requires building at 0.6, 0.9 and 1.2 m before trusting it. |
| **Wall corners and T-junctions** | Flat-capped walls leave a notch of (t/2)^2 at every outer corner | Each wall end is extended by half the thickness of the walls it meets (free ends are not extended). Tested: the 8 x 5 box with 0.2 m walls gives a closed ring of 5.20 m2 with no holes, and the point (8.05, -0.05) is inside. |
| **Headless Chromium draws a blank canvas** | Empty screenshots | Software GL flags, a ready flag, a pixel-variance check, and a 2D fallback render (see stage 7). |

### 1. Ingest and normalise
- PDF: prefer vector paths from PyMuPDF. Otherwise render at 200 to 300 DPI.
- Image: OpenCV perspective correction (if a page quad is found), deskew by Hough dominant angle, light denoise.
- Save `normalised.png` and the transform to the original.

### 2. Calibration: the image-to-metres transform

Metre coordinates need a mapping to pixels or nothing can be overlaid. The plan stores it explicitly:

```json
"image": {"file": "normalised.png", "px_per_m": 100.0, "origin_px": [100, 700], "flip_y": true,
          "anchors": [{"m": [0,0], "px": [100,700]}, {"m": [8,0], "px": [900,700]}],
          "anchor_resid_m": 0.003, "scale_source": "dimension_chain"}
```

Pixel = (`origin_x + s*x`, `origin_y - s*y`). The transform is fitted from 2 or more **anchors** (a point whose metre coordinates are known and whose pixel position is read from the image), by least squares:

```python
import numpy as np
def fit_transform(anchors):               # image already deskewed, so no rotation term
    A, b = [], []
    for a in anchors:
        (x, y), (u, v) = a["m"], a["px"]
        A += [[x, 1, 0], [-y, 0, 1]]; b += [u, v]          # u = s*x+ox ; v = -s*y+oy
    (s, ox, oy), *_ = np.linalg.lstsq(np.array(A, float), np.array(b, float), rcond=None)
    res = [np.hypot(s*a["m"][0]+ox-a["px"][0], -s*a["m"][1]+oy-a["px"][1])/s for a in anchors]
    return {"px_per_m": s, "origin_px": [ox, oy], "flip_y": True, "anchor_resid_m": max(res)}
```

Scale priority, with the winner recorded in `scale_source`: (1) printed dimension chains, (2) a scale bar, (3) a stated ratio (1:100) with the PDF page size, (4) a standard door width, always flagged.

**v1 without CV:** a helper `grid.py` draws a labelled pixel grid (every 100 px) over the image and saves `grid.png`. Claude views it, reads the pixel position of the outer corners (and the ends of one printed dimension) as anchors, and `fit_transform` does the rest. A residual above 3% of the plan width means the reading was off, so redo it.

**Snap to the drawing (`snap.py`, numpy and Pillow only, runs in v1).** Claude's pixel reads are off by a few pixels. `wall_lines()` finds the rows and columns that contain a long dark run (an axis-aligned wall) and returns each wall's centre pixel and thickness in pixels. `snap(px, candidates, tol=8)` moves a read to the nearest detected centreline. Tested on a synthetic 1000 x 800 plan with a 20 px outline and a 10 px partition: reads of 112 and 503 snapped to 109.5 and 500.0, and the two thicknesses were reported as 20 and 11 px. This is a real, if small, CV step in the first version. Diagonal walls and fine hatching are not handled, so those fall back to the overlay check.

### 2b. Dimension solver (in v1, not deferred)

Pixel reads and scale can carry 1 to 2% error, which is 8 to 16 cm on an 8 m wall. So the printed dimensions, not the pixels, set the final coordinates. Each wall position along an axis is one unknown. Each printed dimension is one linear equation between two of them, with the face offsets from `basis` already applied. The solver minimises the dimension residuals, with a very weak pull toward the pixel-read values only to fix the free translation:

```python
import numpy as np
def solve_axis(init, eqs, prior=1e-3):
    """init: {coord_name: pixel-read metres}; eqs: [(name_i, name_j, value_m)] meaning x_j - x_i = value.
    Returns solved coords and the worst residual."""
    names = sorted(init); ix = {n: i for i, n in enumerate(names)}
    A, b = [], []
    for n in names:                      # weak prior: fixes translation only
        r = np.zeros(len(names)); r[ix[n]] = prior; A.append(r); b.append(prior*init[n])
    for i, j, v in eqs:
        r = np.zeros(len(names)); r[ix[j]] = 1; r[ix[i]] = -1; A.append(r); b.append(v)
    x = np.linalg.lstsq(np.array(A), np.array(b), rcond=None)[0]
    res = max((abs(x[ix[j]]-x[ix[i]]-v) for i, j, v in eqs), default=0.0)
    return dict(zip(names, x)), res
```

Tested: pixel reads of x = 0.05, 4.10, 8.10 m with printed 4.00, 4.00 and 8.00 m dimensions come out as 0.083, 4.083, 8.083, so spacings are exactly 4.00 m and the whole plan is shifted by 3 cm (irrelevant, since only relative position matters). Conflicting dimensions (the chain adds to 40'-0" but the overall says 40'-6") leave a residual, which is reported per dimension and never hidden. Write the solved values back into `plan.json` walls, run the solver once for x and once for y, and then run the checker below. For orthogonal plans this makes accuracy depend on the printed numbers and not on how well Claude reads pixels.

### 3. Extraction into plan.json

Two reader modes, so it is clear what actually runs:

- **Reader A, the semantic reader (v1 default, interactive):** Claude Code views `grid.png` and tiles, then writes plan.json using the schema. The scripts only validate and build. No API key needed.
- **Reader A, automated variant (later):** a script calls the Anthropic API with the image, the schema and instructions, and gets a draft plan.json in pixel coordinates. This needs an API key, which in this cloud session should be requested with the credential tool, never pasted in chat.
- **Reader B, the geometric reader (classical CV, later; `snap.py` is its first piece):** returns **centrelines plus thickness** in pixels: for double-line walls it first pairs parallel line segments (gap within 5 to 40 cm), then outputs the midline. For solid fill it uses a skeleton plus the distance transform. Vector PDFs give exact segments.
- **Merge rule:** Reader A is the Claude vision reader (interactive or API, same output format) and Reader B is the classical CV reader. Semantics (type, label, swing) come from A. Each A wall snaps to a B wall when the angle differs by less than 5 degrees, the perpendicular distance is under 10 cm, and the segments overlap, centreline to centreline, so snapping never moves a wall by half its thickness. A wall found by only one reader is kept with `confidence: "low"`. OCR text gives dimensions, and Claude vision arbitrates when OCR and the grammar disagree.

### 4. The plan file (schema)

```json
{
  "units": "m", "default_height": 2.7,
  "image": {"file": "normalised.png", "px_per_m": 100.0, "origin_px": [100,700], "flip_y": true,
            "anchors": [], "scale_source": "dimension_chain"},
  "walls": [
    {"id": "w1", "a": [0,0], "b": [8,0], "thickness": 0.2, "kind": "exterior"},
    {"id": "w5", "a": [4,0], "b": [4,5], "thickness": 0.1, "kind": "interior"},
    {"id": "v1", "a": [4,2.5], "b": [8,2.5], "thickness": 0.01, "kind": "virtual"}
  ],
  "openings": [
    {"id": "d1", "type": "door", "wall": "w5", "offset": 1.0, "width": 0.9, "height": 2.1,
     "sill": 0, "swing": "left", "width_source": "default"},
    {"id": "n1", "type": "window", "wall": "w1", "offset": 2.0, "width": 1.5, "height": 1.2,
     "sill": 0.9, "width_source": "printed"}
  ],
  "rooms": [{"id": "living", "label": "Living", "seed": [2,2], "floor": "wood"},
            {"id": "kitchen", "label": "Kitchen", "seed": [6,1], "floor": "tile"}],
  "dimensions": [{"id": "k1", "value_m": 7.8, "axis": 0, "walls": ["w4","w2"], "basis": ["inside","inside"]}],
  "warnings": []
}
```

- Coordinates are metres, y up. The `image` block maps them to pixels.
- `kind` is `exterior`, `interior` or `virtual`.
- A room's `seed` is any point inside it. It is how a labelled room is matched to an anonymous polygon.
- `dimensions` records which walls a printed value spans, along which axis (0 = x, 1 = y), and the basis at each end.
- Every value not read from the plan carries a `*_source` field, so the report can list guesses.

### 5. Validate and overlay (the quality gate, in code)

1. Every opening lies within its wall (`offset + width <= length`), openings on a wall do not overlap, and no opening's footprint touches another wall.
2. Endpoints snap within tolerance, and no wall is shorter than 0.3 m.
3. Rooms polygonise, every seed lands in exactly one loop, and every loop has a seed (else warning).
4. Footprint area is within 5% of any printed area.
5. Printed dimensions, face-aware:

```python
SGN = {"outside": 1, "inside": -1, "centre": 0}
def check_dims(plan, tol=0.02):
    W = {w["id"]: w for w in plan["walls"]}; bad = []
    for d in plan["dimensions"]:
        wa, wb = (W[i] for i in d["walls"]); ax = d["axis"]
        for w in (wa, wb):               # each wall must be perpendicular to the axis: constant coordinate along it
            if abs(w["a"][ax]-w["b"][ax]) > 1e-3:
                raise ValueError(f"dimension {d['id']}: wall {w['id']} is not perpendicular to axis {ax}")
        ca, cb = wa["a"][ax], wb["a"][ax]            # constant, so a/b order is irrelevant
        got = (abs(cb-ca)
               + SGN[d["basis"][0]]*wa["thickness"]/2 + SGN[d["basis"][1]]*wb["thickness"]/2)
        if abs(got-d["value_m"]) > tol: bad.append((d["id"], round(got,3), d["value_m"]))
    return bad
```

   Tested: two 0.2 m walls at x=0 and x=8 give 7.8 inside, 8.2 outside, and a printed 8.0 inside is flagged. A horizontal wall listed for axis 0 now raises an error instead of returning a wrong number. For a dimension that spans a wall and a room edge, list the two bounding walls.
6. `overlay.py` converts every wall, opening and room seed to pixels with the `image` block and draws them over the source image to `overlay.png`. This is the human check and it takes under 10 seconds.

### 6. Geometry (deterministic Python; tested on a sample plan)

```python
import json, sys, numpy as np, trimesh
from shapely.geometry import LineString, Point, Polygon
from shapely.ops import unary_union, polygonize
from trimesh.visual.material import PBRMaterial
from trimesh.visual import TextureVisuals

def polys(g): return [] if g.is_empty else list(getattr(g, "geoms", [g]))

def extrude(g, h, z0=0.0):                       # loops over every polygon of a MultiPolygon
    out = []
    for p in polys(g):
        if p.area < 1e-6: continue
        m = trimesh.creation.extrude_polygon(p, h); m.apply_translation([0, 0, z0]); out.append(m)
    return trimesh.util.concatenate(out) if out else None

def skin(m, name, rgba):
    m.visual = TextureVisuals(material=PBRMaterial(name=name, baseColorFactor=rgba, roughnessFactor=0.9))
    return m

def build(plan, cut_height=None):                # cut_height gives the low-wall cutaway variant
    H = cut_height or plan["default_height"]
    real = [w for w in plan["walls"] if w.get("kind") != "virtual"]
    byid = {w["id"]: w for w in plan["walls"]}
    def ends(w):                                 # extend each end by half the thickness of walls it meets
        p = [np.array(w["a"], float), np.array(w["b"], float)]; u = (p[1]-p[0]) / np.linalg.norm(p[1]-p[0]); out = []
        for i, q in enumerate(p):
            ts = [v["thickness"] for v in real if v is not w and LineString([v["a"], v["b"]]).distance(Point(q)) < 1e-3]
            out.append(q + (u if i else -u) * (max(ts)/2 if ts else 0.0))
        return out
    fp = lambda w: LineString(ends(w)).buffer(w["thickness"]/2, cap_style=2)
    ext = unary_union([fp(w) for w in real if w["kind"] == "exterior"])
    inn = unary_union([fp(w) for w in real if w["kind"] != "exterior"]).difference(ext)
    foot = unary_union([ext, inn])
    parts = {"wall_ext": extrude(ext, H), "wall_int": extrude(inn, H)}
    cuts = {"wall_ext": [], "wall_int": []}
    for o in plan["openings"]:
        w = byid[o["wall"]]; a, b = np.array(w["a"]), np.array(w["b"]); u = (b-a)/np.linalg.norm(b-a)
        n = np.array([-u[1], u[0]]); t = w["thickness"]; s0, s1 = o["offset"], o["offset"]+o["width"]
        region = Polygon([a+u*s0+n*t/2, a+u*s1+n*t/2, a+u*s1-n*t/2, a+u*s0-n*t/2])
        for v in real:                           # never notch a neighbouring wall
            if v["id"] != w["id"] and fp(v).intersection(region).area > 1e-4:
                raise ValueError(f"opening {o['id']} overlaps wall {v['id']}")
        c = a + u*(s0+s1)/2
        ch = min(o["height"], H - o["sill"])
        if ch < 0.05:                            # opening starts at or above the cut height
            plan.setdefault("warnings", []).append(f"opening {o['id']} skipped at cut height {H}"); continue
        cut = trimesh.creation.box(extents=[o["width"], t+0.02, ch])
        T = trimesh.transformations.rotation_matrix(np.arctan2(u[1], u[0]), [0,0,1])
        T[:3,3] = [c[0], c[1], o["sill"] + cut.extents[2]/2]; cut.apply_transform(T)
        cuts["wall_ext" if w["kind"] == "exterior" else "wall_int"].append(cut)
    colors = {"wall_ext": [.9,.9,.88,1], "wall_int": [.95,.95,.95,1]}
    scene = trimesh.Scene()
    for k, m in parts.items():
        if m is None: continue
        for c in cuts[k]: m = m.difference(c, engine="manifold")
        assert m.is_watertight, k + " not watertight"
        scene.add_geometry(skin(m, k, colors[k]), node_name=k)
    # rooms: centrelines including virtual walls -> polygons -> labelled by seed point
    faces = list(polygonize(unary_union([LineString([w["a"], w["b"]]) for w in plan["walls"]])))
    used = set()
    for r in plan["rooms"]:
        hit = [i for i, p in enumerate(faces) if p.contains(Point(r["seed"]))]
        if not hit: plan.setdefault("warnings", []).append(f"room {r['id']} seed in no closed loop"); continue
        used.add(hit[0]); m = extrude(faces[hit[0]].difference(foot), 0.1, -0.1)   # floor excludes wall volume
        if m is not None: scene.add_geometry(skin(m, "floor_"+r["id"], [.7,.55,.4,1]), node_name="floor_"+r["id"])
    for i, p in enumerate(faces):
        if i not in used:
            plan.setdefault("warnings", []).append(f"closed loop {i} has no room label")
            m = extrude(p.difference(foot), 0.1, -0.1)
            if m is not None: scene.add_geometry(skin(m, f"floor_unlabeled{i}", [.6,.6,.6,1]), node_name=f"floor_unlabeled{i}")
    return scene

if __name__ == "__main__":
    plan = json.load(open(sys.argv[1]))
    sc = build(plan, float(sys.argv[3]) if len(sys.argv) > 3 else None)
    sc.apply_transform(trimesh.transformations.rotation_matrix(-np.pi/2, [1, 0, 0]))   # plan Z-up -> glTF Y-up
    sc.export(sys.argv[2]); print("ok", plan.get("warnings"))
```

Run `python build.py plan.json house.glb` and `python build.py plan.json house_cut.glb 1.2`. Material names (`wall_ext`, `wall_int`, `floor_<room id>`) are set so Blender or three.js can re-skin them. The scene is rotated to Y-up as the last step, so `house.glb` is valid glTF and imports upright in Blender. Tested on an 8 m by 5 m plan with a virtual wall, a detached wall, a door and a window. It exported, and a door placed 2 cm from the exterior wall was rejected with a clear message. Re-run these checks after any change to the corner code: footprint area equals the closed-ring area, no interior holes besides rooms, watertight, bounds in Y equal the wall height.

Window glass and door leaves are added later as thin separate meshes inside each opening. If `manifold3d` fails to install, split each wall into pieces around the opening (lintel and sill blocks) with no booleans.

Steps that worked here (a pixel-variance check confirmed non-blank PNGs):

1. Serve over HTTP (`python -m http.server 8123`). `file://` blocks `fetch` of the GLB and module imports.
2. Load three.js from the local `node_modules` through an import map, not a CDN.
3. Launch Chrome with software GL: `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist`.
4. The viewer sets `window.__ready = true` after the GLB loads and one frame is rendered (or `window.__error`), and the screenshot script waits for it.
5. After each screenshot, check that the image has more than a few distinct grey values. If not, use `top_2d.png`.
6. Cutaway: render `house_cut.glb` (1.2 m walls, capped), instead of clipping planes, which leave hollow walls.

### 8. Materials and lighting
- Per-object material names, defaults: matte white walls, wood or tile floors from the room's `floor` field (bathroom and kitchen default to tile), glass with low roughness.
- Presets: **Clay** (white material, soft light, best for checking geometry), **Daylight** (sun plus sky, openings let light in), **Evening** (warm point light per room seed).
- Lighting changes looks only, never geometry, so do not use it to judge accuracy.

### 9. Output files
- `plan.json` (source of truth), `report.md` (scale source, guesses, warnings, dimension residuals), `overlay.png` (proof of extraction).
- `house.glb` (primary), `house_cut.glb`, optionally `house.obj` or `.fbx`, and `house.blend` if Blender is used.
- Renders: `top_house.png`, `iso_house.png`, `iso_house_cut.png`, `top_2d.png` (fallback), and optionally a turntable MP4.

## Risks that remain

1. **Vision-model pixel imprecision.** Claude's pixel reads can be off by 1 to 2%, which is why the final coordinates come from the printed dimensions (stage 2b) and the pixel reads are snapped to detected wall lines. Anchor residuals and the overlay catch the rest. Where a plan has few printed dimensions, accuracy falls back to the pixel scale and is stated as lower in `report.md`. Faint or hand-drawn plans are the weakest case.
2. **API-driven automation** needs a key and costs money per plan. Keep the interactive mode as the default until it is proven.
3. **Blender may not be installable** here. The Python plus three.js path does not need it, so build that first.
4. **Boolean engine failure.** Use the no-boolean fallback above.
5. **Privacy.** Plans may carry addresses. Keep processing local and do not send plans to third-party render services without telling the user.
6. **Scope creep** into furniture, stairs, multi-storey. Keep them out of v1. Multi-storey later means one plan.json per level, stacked.
7. **Non-orthogonal plans:** `check_dims` and the solver assume axis-aligned walls and now raise an error otherwise. For angled walls, skip them and rely on the overlay.
8. **No full automation in v1.** A new plan still needs a Claude Code session as the reader (Reader A). Automating that is step (d) below, and OCR plus Reader B remove the dependence on it for clean plans. This is stated up front so v1 is not mistaken for a one-click converter.

## Minimal first version (a day or two)

Scope: one rectilinear single-storey plan, clean image or vector PDF, dimensions printed. **No OCR and no full CV reader**, but it does include the numpy snap helper and the dimension solver, so accuracy does not rest on pixel reading. A Claude Code session acts as the reader; the scripts do everything else deterministically.

1. Run the stage 0 smoke test.
2. `grid.py` makes `grid.png`. Claude views it, picks anchors, and `fit_transform` fills `image`. `snap.py` snaps the reads to the drawn walls.
3. Claude writes `plan.json`, including `dimensions` with their `basis`, then `solve_axis` (stage 2b) fixes wall coordinates to the printed dimensions.
4. `validate.py` runs checks 1 to 5 and `overlay.py` writes `overlay.png`. The user or Claude looks at it and fixes plan.json until it matches.
5. `build.py` makes `house.glb` and `house_cut.glb`.
6. `viewer.html` and `shot.py` make `top`, `iso` and `iso_cutaway` PNGs, with the 2D fallback.
7. `report.md` lists scale source, guessed values and warnings.

Done when, on 3 sample plans (a clean box, an L-shape with 4 rooms and a virtual wall, a plan with a door on every wall), printed dimensions match within the 2 cm tolerance using the correct basis, the GLB is watertight, door and window counts match the plan, the overlay visibly matches, and the screenshots are non-blank.

Then add in order: (a) OCR (so dimensions are read automatically; the solver already exists), (b) CV wall snapping, (c) PDF vector parsing, (d) the automated API reader, (e) Blender renders, (f) AI beautification, (g) multi-storey.

## Test checklist for each plan

- [ ] `image.scale_source` is printed dimensions, not a default, and anchor residual is small.
- [ ] Every printed dimension checks within 2 cm using the right basis.
- [ ] Every room has a floor and a label, and no loop is unlabelled.
- [ ] Meshes watertight, no notched corners (footprint area equals the ring area), no opening floating, door and window counts match the plan.
