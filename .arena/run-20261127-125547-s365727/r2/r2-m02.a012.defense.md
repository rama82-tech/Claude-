ATTACK 1: CONCEDE. Wall meshes were anonymous, so check (e) could not be run. Fixed: meshes and GLB nodes are named by wall id, and a new check_glb.py compares every wall in model.glb with plan.json (8 of 8 matched within 5 mm). Section 11(e) now uses it.
ATTACK 2: CONCEDE. The count gate did block all labels when the extractor missed or invented an opening. Replaced: labels for existing ids always apply, a mismatch is reported with its direction and the fix (add_openings or remove_openings, both new), and only self-contradictory typing is refused. Tested a mismatch, an add plus remove, and stale ids.
ATTACK 3: CONCEDE. Re-running did overwrite edits and renumber ids. Fixed: ids are position-based (stable across a --max-hole re-run, tested), plan2ir.py writes only plan.raw.json, hand and Claude decisions live in edits.json, and apply_edits.py merges them into plan.json and reports stale ids instead of failing.
ATTACK 4: CONCEDE. The skew mitigation had no code. Added deskew.py (Hough angle, rotate, re-measure) and a skew warning in plan2ir.py. Measured: a 0.8 degree scan gave 0.22 m walls, 2 of 3 openings and a 17 m2 footprint; after deskew 0.16 m, 3 of 3 and 36.2 m2. Angle accuracy is about 0.2 degrees, stated.
ATTACK 5: CONCEDE. --check used the same segment as --dim and proved nothing. The test plan now has a vertical 5000 dimension, the quickstart checks that one, and the docs say never to reuse the --dim segment.
ATTACK 6: CONCEDE. Added pdf2png.py (PyMuPDF, installed and tested on a toy PDF; prints implied ppm and whether the page is vector or scan) and put pymupdf in the install line. Vector-coordinate extraction is still Phase 2 and is labelled untested.
ATTACK 7: CONCEDE. Length arguments now parse metres, mm, cm and feet-inches (12'-6", 41' 3 1/2"); tested, 26'-3" gave 8.001 m. The documentation warns to check with a second dimension to catch conversion slips.
